# 可用性测试 · 术语表（中英对照）

> 页码口径：`（pN）`= Rubin & Chisnell；`（B pN）`= Barnum。
> 术语按主题分组，同组内按英文字母序。

---

## 一、测试类型与阶段

| 中文 | 英文 | 释义 | 出处 |
|---|---|---|---|
| 形成性测试 | **formative testing / study** | 开发过程中做，目的是诊断并修问题。Rubin 称其为 exploratory 的同义语 | B p45；p67 |
| 总结性测试 | **summative testing / evaluation** | 开发末期做，用于确认是否满足要求、产出指标 | B p45 |
| 探索性测试 | **exploratory study / test** | 早期，检验初步设计概念与"关于用户的假设"，重定性 | p67–p69 |
| 评估性测试 | **assessment test** | 中早期，高层设计已定，检验低层操作；必须真做任务+采量化 | p72–p73 |
| 验证性测试 | **validation test** | 后期，**对预设基准**打分（够不够格） | p73 |
| 确认性测试 | **verification test** | 后期，**确认老问题已修且未引入新问题** | p73 |
| 比较测试 | **comparison test** | 两个及以上明显不同的方案对比；可叠加于任一类，产出常为**混血方案** | p75–p76 |
| 迭代测试 | **iterative testing / design** | 设计—测—改的循环；"discount"模式下每轮 4–5 人/格子 | p66、p111；B p42 |
| 基线测试 | **benchmark test** | 计时/成功率对照既有基准的测试 | p73、p81 |
| 后续研究 | **follow-up study** | 发布后收集下一版数据；原文称其为"最真实的可用性评估" | p58 |

## 二、主持形态（moderated / unmoderated）

| 中文 | 英文 | 释义 | 出处 |
|---|---|---|---|
| 有主持 | **moderated** | 有主持人在场（"present"），可追问 | B p41 |
| 无主持 | **unmoderated** | 用基于网页的应用自行执行，无人追问 | B p41 |
| 同步（远程） | **synchronous / moderated remote** | 主持人与被试实时联网，像实验室但异地 | B p42 |
| 异步（远程） | **asynchronous / unmoderated / automated** | 不需同时在场，应用自动采集与提问 | B p44 |
| 自动化测试 | **automated testing** | 「completely unmoderated by humans」，程序采集数据并在特定点提问 | p311 |
| 远程测试 | **remote testing** | 用电话+电脑测屏基界面；看不到肢体语言，但能听能看屏 | p310 |
| 现场/入户测试 | **in-home / on-site testing**（"follow me home"） | 在被试真实环境做；Intuit 创始人 Scott Cook 所创说法 | p312 |
| 旁坐式 | **sit-by session** | 主持人与被试同室；适合探索与纸质原型 | p91–p92 |
| 单向镜控制室 | **classic testing laboratory** | 被试独处，其余人在控制室经单向镜观察；可容 4–12 观察者 | p108–p109 |
| 电子观察室 | **electronic observation room** | 隔壁房间看监视器；可自由进出、可互相讨论 | p107 |
| 极简便携实验室 | **minimalist portable lab** | 原文推荐给"刚开始做测试"的组织 | p110、p148–p149 |
| 豚鼠综合征 | **"guinea pig" syndrome** | 控制室布置使被试过度自觉；对技术自信低者尤甚 | p110、p148 |
| 观察者效应 | **observer effect** | 观察者（含主持人）对被试行为的影响 | B p245 |

## 三、人与样本

| 中文 | 英文 | 释义 | 出处 |
|---|---|---|---|
| 用户画像 | **user profile** | 目标受众的行为、熟练度、知识、人口统计等描述 | p153–p154 |
| 需求（门槛） | **requirements** | 被试必须已具备的知识；不满足即淘汰 | p159 |
| 分类器 | **classifiers** | 将被试分组的属性，用于解释测试中出现的差异 | p159 |
| 人群格子 | **audience cell / cell** | 矩阵中的一个用户群；样本量按格子计 | p110、p163 |
| 矩阵测试设计 | **matrix test design** | 让每个格子都有人，避免遗漏某类用户 | p163 |
| 最不熟练用户 | **least competent user (LCU)** | 「represents the least skilled person who could potentially use your product」；每样本至少 1 人 | p184 |
| 明星被试 | **"ringers"** | 被推荐来的顶尖表现者；会让结果虚高。最多 1–2 个 | p185–p186 |
| 职业被试 | **cheaters and repeaters** | Craigslist 等渠道中编造身份或凡有招募就报名的人 | p177 |
| 筛选问卷 | **screener / screening questionnaire** | 用于判定资格与选择的问卷（含终止项与招募员注记） | p164–p169 |
| 准则测验 | **criterion test** | 用实际测验或矩阵核实熟练度，替代自评 | p167 |
| 超招比例 | **over recruit**（"recruit 12 for 10"） | 招募机构通常多招 20% 以补缺席 | p179 |
| 试验性被试 | **pilot participant** | 用于试点的人；其数据能否计入取决于改动大小 | p253；B p213 |

## 四、任务与材料

| 中文 | 英文 | 释义 | 出处 |
|---|---|---|---|
| 任务清单 | **task list** | 给团队看的任务表；含描述、材料与机器状态、SCC、基准 | p117 |
| 任务场景 | **task scenario** | 给被试看的版本：加情境、动机、真实数据；一个场景可包多条任务 | p220 |
| 成功完成标准 | **successful completion criteria (SCC)** | 判定任务成功的边界；写不出来说明设计没想清 | p118 |
| 基准（计时） | **benchmark (timing)** | 任务允许的最长时间；算法为 6 人估算均值 × 2.5 | p119–p120 |
| 横向原型 | **horizontal representation** | 能左右走、不能深入 | p69 |
| 纵向原型 | **vertical representation** | 能沿某功能深入多层 | p69 |
| 引导脚本 | **orientation script**（introduction script） | 开场念给被试的逐字稿 | p193–p199 |
| 背景问卷 | **background questionnaire** | 测前收集经历/态度/偏好，用于解释表现 | p200 |
| 前测问卷 | **pre-test questionnaire** | 测前测态度与前置知识 | p174、p181 |
| 后测问卷 | **post-test questionnaire** | 测后收整体感受；可用 Likert、语义差异等 | p192–p198 |
| 回述指南 | **debriefing topics guide** | 用于会后备询的议题清单 | p191、p199 |
| 观察者准则 | **guidelines for observers** | 六条（准时、全程、静音、不出声、只问开放式、保密） | p193 |
| 任务清单计数器 | **task clock** | 让被试从电脑逐条取任务并自动计时的做法 | p224 |

## 五、主持与提问技术

| 中文 | 英文 | 释义 | 出处 |
|---|---|---|---|
| 出声思维 | **think-aloud / thinking aloud / verbal protocol** | 边做边说；会**减慢并减少错误** | p242–p244 |
| 语言协议 | **verbal protocol** | 出声思维产生的连续口头记录 | p92 |
| 回溯复盘 | **retrospective review / replay the test** | 任务结束后回看录像再问；适合边说边做困难者 | p92–p93、p235 |
| 协同发现 | **co-discovery** | 两名被试同时进行，互相交流；可按脚本时点换手 | p306–p307 |
| 渐进披露/逐级提示 | **gradual disclosure / graduated prompting** | 只给"刚好能继续"的信息；分四档并计数 | p304–p305 |
| 弹性脚本 | **flexible scripting**（interview-based testing） | 先访谈再与被试共同确定任务 | p303–p304 |
| 中性提示 | **neutral probing** | 不暗示对错与偏好的追问 | p246；B p233 |
| 引导性提问 | **loaded question** | 例："大多数人觉得这很容易，你呢？"——禁用 | p246 |
| 镜像反映 | **acting as a mirror** | 复述被试的话以助其展开 | p245 |
| 装傻 | **"play dumb"** | 扮演"只负责采集数据的技术员"，降低求助预期 | p95 |
| 救场 | **rescuing** | 过早介入帮忙；应避免 | p209 |
| 主持禁语 | **"Top Ten" of things not to say** | 十句绝不能说的话 | p265–p266 |
| 平衡赞扬 | **balanced praise** | 失败与成功都给正向反馈（Barnum） | B p232 |
| 发现会 | **findings meeting**（affinity 过程） | 团队读日志→写便签→归组→命名 | B p269 |

## 六、分析与严重度

| 中文 | 英文 | 释义 | 出处 |
|---|---|---|---|
| 发现 | **finding** | 从观察中得出的**可被反驳的推断**，非数据本身 | p307 |
| 结果 | **results** | 收集并分析的数据本身 | p307 |
| 全局发现 | **global finding** | 反映贯穿全产品的问题；通常是重要发现 | B p285 |
| 局部发现 | **local finding** | 只出现在某一屏/某一步 | B p286 |
| 严重度评级 | **severity rating** | 按对用户体验的影响排序 | p300；B p286 |
| 不可用 | **unusable**（Rubin 4 分） | 用户不能**或不愿**使用 | p300 |
| 严重 | **severe**（Rubin 3 分） | 会用但严重受限、极难绕过 | p300 |
| 中等 | **moderate**（Rubin 2 分） | 能用，需中等努力绕过 | p300 |
| 刺激物/小烦 | **irritant**（Rubin 1 分） | 偶发/易绕过/装饰性 | p300 |
| 灾难 | **catastrophe**（Barnum 1 分） | 完不成 / 完成但极度恼火 / **需要协助** | B p287 |
| 严重问题 | **serious problem**（Barnum 2 分） | 挫败但能过关 | B p287 |
| 装饰性问题 | **cosmetic problem**（Barnum 3 分） | 迟疑或选错但能自行纠正 | B p287 |
| 频率评级 | **frequency ranking** | ≥90%/51–89%/11–50%/≤10% → 4/3/2/1 | p301 |
| 持久性 | **persistence（of the problem）** | 被试能否学会避免/克服；Barnum 的第三维 | B p286 |
| 关键度 | **criticality** | 严重度 + 发生概率（Rubin 的合成算式） | p299 |
| 错误来源分析 | **source of error analysis** | 逐任务归因到产品组件；从"任务导向"转"产品导向" | p299 |
| 遗漏型错误 | **errors of omission** | 该做没做 | p260 |
| 施行型错误 | **errors of commission** | 做了不该做的 | p260 |
| 任务准确度 | **task accuracy** | 三种口径：含协助/纯成功/基准内成功 | p288 |
| 事后合理化 | **rationalize（behavior）** | 回溯复盘的风险：被试改写当时想法 | p93 |

## 七、伦理与合规

| 中文 | 英文 | 释义 | 出处 |

## 九、易混术语辨析

| 容易混淆 | 区别 | 出处 |
|---|---|---|
| **formative vs exploratory** | 在 Rubin 书里是同义语；Barnum 用 formative 作主分类 | p67；B p45 |
| **validation vs verification** | validation=对基准打分；verification=老问题修没修。**必须分开陈述** | p73 |
| **progressive disclosure vs graduated prompting** | 前者是交互设计概念（向导式界面）；后者是测试技术（给提示） | p304 |
| **severity vs criticality** | severity 只看"多严重"；criticality = severity + 频率 | p299–p301 |
| **global vs local finding** | 影响范围，不是严重度；全局问题即使 2 分，修复面积也更大 | B p284–p286 |
| **results vs findings** | 结果可数；发现是推断，需可被反驳 | p307 |
| **moderated vs synchronous** | moderated 指"有人在主持"；synchronous 指"同时在场"。远程有主持即两者兼具 | B p42 |
| **unmoderated vs asynchronous vs automated** | Barnum 视为同义三说法；Rubin 用 automated 更偏"程序采集" | B p44；p311 |
| **think-aloud vs co-discovery** | 前者对主持人说，后者对被试之间说；后者更自然但改变了人数条件 | p242、p306 |
| **pilot vs walkthrough** | pilot 用真实用户走全流程；walkthrough 用"宽容用户"预演找问题 | B p212 |
