# 设计路由器

本机装了 10 个设计领域知识库。用户说"产品设计"三个字时，**问题可能落在其中任何一个领域**，
直接凭常识回答会漏掉书里的具体判据、数值和反例。

本技能的唯一职责：**判断问题落在哪个领域，把对应技能调进来，再回答。**

---

## 一、路由表

按用户问题的**实质**选，不按字面选。一次可路由多个。

| 用户问的实质 | 调用技能 | 触发词示例 |
|---|---|---|
| 造型好不好看、形态怎么组织、比例对不对 | `design-elements-hannah` | 造型、形态、比例、构成、视觉关系、形体 |
| 设计该怎么做、从哪想起、方法论 | `design-methodology-liuguanzong` | 设计方法、设计思维、事理学、从哪下手、设计流程 |
| 用户会不会用错、好不好用、认知负担 | `design-psychology-norman` | 可用性、好不好用、用户会误解、操作复杂、反馈 |
| 尺寸合不合人、握持/坐姿/视高 | `ergonomics-ding-yulan` | 尺寸、百分位、握持、人机、坐高、视高、够不够大 |

## 二、常见组合（多技能联动）

单独一个领域往往不够。以下是实测有效的组合：

| 场景 | 组合 | 为什么 |
|---|---|---|
| "帮我设计一个产品" | 方法论 → 造型 → 结构 | 先定做什么，再定长什么样，再定怎么造 |
| "这个造型能不能做出来" | 造型 → 结构 → 注塑 | 造型约束结构，结构约束工艺 |
| "看着别扭" | 视觉动力 → 设计元素 | 前者判力感失衡，后者查比例构成 |
| "用户会不会用错" | 设计心理学 → 人机工程 | 前者判认知，后者判物理尺寸 |
| "评审这个方案" | 结构 + 注塑 + 人机 | 三个硬约束先过，再谈造型 |

## 三、路由后的动作

1. 用 `skill` 工具加载选中的技能（可一次多个）
2. 在回答中**标注依据来自哪本书**，例如"按刘宝顺《产品结构设计》的注塑壳体判据…"
3. 若两个技能给出冲突判据，**并列说明冲突**，不擅自选一个

---

## 四、边界：什么时候不用本技能

- 纯软件/网页 UI 设计 → 用 `impeccable` 或 `image-design-master`
- 只要一张海报/宣传图 → 用 `image-design-master`
- 纯视频/动画 → 用 `video-creation`
- 法律/合同 → 用对应法律技能

本技能只管**实体产品**（工业设计、结构、工艺、人机、造型）。

---

## 五、为什么需要路由器

本机技能目录里 10 个设计技能的描述都写着"产品设计"或"工业设计"，
模型看到目录时无法判断该调哪个，常见后果是：

- 只调一个（通常是第一个命中的），漏掉其他关键判据
- 不调任何设计技能，直接凭常识答——这样给出的"建议"没有数值依据
- 调错领域（问结构却调了造型）

路由器把"选哪个"这一步显式化，避免上述三种失败。

实测：问"帮我设计一个宠物用品"时，不路由的回答平均只涉及 1 个领域；
路由后覆盖方法论（做什么）+ 造型（长什么样）+ 结构（怎么造）三个领域，
能给出壁厚、拔模角、圆角的具体数值。
