# 设计路由器

本机装了 13 个设计领域知识库：**表 1.0 列 10 个（7 个设计理论 + 1 个交付 + 1 个工艺 + 1 个史论），表 1.1 列 3 本 SOLIDWORKS**。
用户说"产品设计"三个字时，**问题可能落在其中任何一个领域**，
直接凭常识回答会漏掉书里的具体判据、数值和反例。

本技能的唯一职责：**判断问题落在哪个领域，把对应技能调进来，再回答。**

## 二、常见组合（多技能联动）

单独一个领域往往不够。以下是实测有效的组合：

| 场景 | 组合 | 为什么 |
|---|---|---|
| "帮我设计一个产品" | 方法论 → 造型 → 结构 | 先定做什么，再定长什么样，再定怎么造 |
| "这个造型能不能做出来" | 造型 → 结构 → 注塑 | 造型约束结构，结构约束工艺 |
| "看着别扭" | 视觉动力 → 设计元素 | 前者判力感失衡，后者查比例构成 |
| "用户会不会用错" | 设计心理学 → 人机工程 | 前者判认知，后者判物理尺寸 |
| "评审这个方案" | 结构 + 注塑 + 人机 | 三个硬约束先过，再谈造型 |
| **"这个外观能不能造出来、要多少钱"** | **造型 → 结构 → 注塑 → 2025（DFM）** | **后者给 DFMXpress 的检查项** |
| **"曲面分件怎么拆"** | **曲面（主模型）→ 结构（分件）** | **曲面给分割方法，结构给壳体准则** |
| **"工程图怎么出、公差怎么定"** | **实战（出图）→ 实战§6.4c/2025§14.1（公差分析）** | **标完必须验累积误差** |
| **"零件设计完了要交付给客户"** | **实战（eDrawings）** | **客户看 2D 看不懂 → eDrawings 能立起来看** |

### 2.1 SOLIDWORKS 三本的联动（实测有效）

| 场景 | 组合 | 为什么 |
|---|---|---|
| **"做个塑料件，外观要漂亮还能造"** | **造型 → 结构 → 2025（DFM）→ 注塑** | 造型定语言 → 结构定壁厚拔模 → DFM 查加工 → 注塑查缺陷 |
| **"曲面零件要出图"** | **曲面（建模）→ 实战（工程图）** | 曲面 7 章只讲建模，出图在实战 ch06 |
| **"装配怎么设计"** | **实战 ch04（自顶向下）→ 2025 ch06（配合类型学）** | **前者给流程，后者给配合分类** |
| **"要考 SW 认证"** | **实战 ch99 + 2025（查功能）** | **认证题在实战，功能细节查 2025** |

> **★★★ 判据：SW 三本"同主题不重复"** ——
> 装配体两章：实战讲「自顶向下 28 步 / 爆炸直线 14 步」，2025 讲「干涉检查 / 压缩三态 / 机械配合」。
> **★ 两边都要看，不是二选一。**

## 三、路由后的动作

1. 用 `skill` 工具加载选中的技能（可一次多个）
2. 在回答中**标注依据来自哪本书**，例如"按刘宝顺《产品结构设计》的注塑壳体判据…"
3. 若两个技能给出冲突判据，**并列说明冲突**，不擅自选一个

## 四、边界：什么时候不用本技能

- 纯软件/网页 UI 设计 → 用 `impeccable` 或 `image-design-master`
- 只要一张海报/宣传图 → 用 `image-design-master`
- 纯视频/动画 → 用 `video-creation`
- 法律/合同 → 用对应法律技能
- **SOLIDWORKS API / 二次开发报错** → 用 `solidworks-api-traps`（不是本路由的三本）
  - 本路由的三本讲"**人怎么操作**"，`solidworks-api-traps` 讲"**程序怎么驱动**"

本技能只管**实体产品**（工业设计、结构、工艺、人机、造型、SW 建模）。

## 五、为什么需要路由器

本机技能目录里 13 个设计技能的描述都写着"产品设计"或"工业设计"，
模型看到目录时无法判断该调哪个，常见后果是：

- 只调一个（通常是第一个命中的），漏掉其他关键判据
- 不调任何设计技能，直接凭常识答——这样给出的"建议"没有数值依据
- 调错领域（问结构却调了造型）

路由器把"选哪个"这一步显式化，避免上述三种失败。

实测：问"帮我设计一个宠物用品"时，不路由的回答平均只涉及 1 个领域；
路由后覆盖方法论（做什么）+ 造型（长什么样）+ 结构（怎么造）三个领域，
能给出壁厚、拔模角、圆角的具体数值。
