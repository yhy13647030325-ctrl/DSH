# 19 个设计技能：使用指南

> **这份文件回答一个问题：手上有个设计问题，该按什么顺序、查哪个技能、看哪一节、拿到什么产出。**
>
> 制定日期：2026-11-17｜适用：`design-router` 管辖的 19 个矩阵内技能
> 配套：`SKILL.md`（路由表本体）· `references/REPORT-5-ACTIONS.md`（能力边界与接口实证）

---

## 零、先记住这一条

**任何设计问题，先经 `design-router`，不要自己判断该查哪本。**

不是流程洁癖——19 个技能里有 **4 组"看起来该查 A、其实该查 B"** 的陷阱，凭直觉必错其中至少一组：

| 你的直觉 | 实际该查 | 为什么 |
|---|---|---|
| **选材 → SW 三本**（"材料"在 SW 里出现 278 次） | **`cmf-system`** | SW 那 278 次是"软件里怎么设材料属性"，不是"这个产品该用什么材料" |
| **作业环境 → 注塑**（482 次） | **`ergonomics-ding-yulan`** | 注塑讲车间温湿度对成型的影响；照明/噪声/振动在人机（237 次） |
| **轮廓 → 造型**（369 : 360，只差 9 次） | **看你要什么** | 建模里怎么定轮廓→`solidworks-surface-advanced`；审美上轮廓怎么读→`product-design-styling-dabbs` |
| **用户研究 → 诺曼**（21 次） | **`user-research-methods`** | 诺曼只有一节方法清单，没有样本量、筛选问卷、编码流程 |

## 一、三条主路

| 路 | 你要什么 | 特征 |
|---|---|---|
| **路 A** | **一个结论**（"这个设计对不对"） | 跨三层，顺序不能倒 |
| **路 B** | **一个产品**（从 0 到能造） | 沿链路推进，每环有交付物 |
| **路 C** | **一个证据**（别拿讨论代替测试） | 三个技能接力，缺一环结论不成立 |

---

## 二、路 A：要一个结论 —— 走三层

### 结构

```
原理层（为什么错）→ 方法层（应该多少）→ 工具层（怎么改）
```

| 层 | 查谁 | 交付什么 |
|---|---|---|
| **原理层** | `design-psychology-norman`（认知/失误）· `design-elements-hannah`（视觉构成）· `visual-dynamics-industrial-design`（力感）· `world-modern-design-history`（年代与流派定位） | **判断依据**：错在哪一类，不是"看着不对" |
| **方法层** | `product-design-styling-dabbs`（造型十阶段）· `ergonomics-ding-yulan`（尺寸/百分位）· `user-research-methods`（研究设计）· `cmf-system`（CMF 决策）· `inclusive-accessibility-design`（排除率） | **具体数值与规则**：多少毫米、选哪档、覆盖到哪一端 |
| **工具层** | `solidworks-practice` / `solidworks-surface-advanced` / `solidworks-2025-mechanical` · `blender-hard-surface` / `blender-manual-reference` | **可执行的建模动作**：命令路径、参数、失败模式 |

### 判据

> **★★★ 顺序不能倒。** 只说"应该改成 R3 圆角"而说不出为什么不是 R1，就还没到方法层；
> 只会建模而说不出该多大，就还停在工具层。

**代价对照**：
- 直接跳工具层 → **建的出来但不知对错**（能把壁厚建成 2.0，不知道为什么不是 1.2）
- 只停原理层 → **说得对但做不出来**（知道该有拔模，不会建、不知度数与方向）

### 典型问法（可直接照抄）

> **"这个手柄用户说握着难受。别急着改模型——先说清三件事：按人机工程这套握持直径应该多少（P5–P95 覆盖到哪）、从视觉构成和力感上看问题出在哪、最后在 SOLIDWORKS 里怎么改形并接顺。三层都给，从'为什么错'开始。"**

命中：`ergonomics-ding-yulan` → `design-elements-hannah` / `visual-dynamics-industrial-design` → `solidworks-practice` / `solidworks-surface-advanced`

## 三、路 B：要一个产品 —— 沿链路推进

### B-1 塑料件：外观漂亮 + 能造

```
cmf-system → product-design-styling-dabbs → product-structure-liubaoshun → product-injection-defects
```

| 环节 | 看哪一节 | 拿到什么产出 |
|---|---|---|
| **CMF 定案** | `cmf-system` ch07 §7.5（选材四步 Translation→Analysis→Identification→Screening+Ranking）、ch06（七行表面规格） | 材料牌号 + 七行规格（硬度/膜厚/温度/曲面/光泽/纹理/色号） |
| **造型语言** | `product-design-styling-dabbs` ch01（视觉主题）、ch03（比例）、ch08（表面） | 视觉主题板 + 比例配置图 |
| **结构可行** | `product-structure-liubaoshun` ch01（壳体）、ch02（连接）、ch05（密封） | 壁厚/拔模/卡扣/密封的结构方案 |
| **开模前风险** | `product-injection-defects` ch01（五类参数）、各案例章（缺陷现象→原因→对策） | 缺陷风险清单 + 对策（可直接用于模具评审） |

### B-2 定 CMF 方案（单点深入）

```
cmf-system（四步选材 + 七行规格）→ 造型（色彩语义）→ 结构（壁厚/异材固定）→ 注塑（缺陷风险）
```

| 环节 | 看哪一节 | 产出 |
|---|---|---|
| 意向与感知 | `cmf-system` ch01（材料两个角色）、ch05（美学与感知属性） | 意向词 → 感知词对（20 对表） |
| 选材 | `cmf-system` ch04 §4.4（四步）、§4.5（六张属性图） | 候选材料 + 材料指数排序 |
| 表面 | `cmf-system` ch06（15 种工艺五列量化表） | 工艺路线 + 参数 |
| 色彩 | `product-design-styling-dabbs` ch10（色彩对比与分区） | 色彩分区方案 |

### B-3 从 0 做造型

```
product-design-styling-dabbs → visual-dynamics-industrial-design → design-elements-hannah
```

| 环节 | 看哪一节 | 产出 |
|---|---|---|
| 流程 | `product-design-styling-dabbs` ch01–ch02（视觉主题、轮廓） | 主题 + 轮廓方向 |
| 诊断 | `visual-dynamics-industrial-design` ch01–ch04（F 假设、倒叙分析、施力者/受力者） | 力感失衡的具体位置 |
| 找形 | `design-elements-hannah` ch02–ch03（主导/次要/附属、三种比例） | 形体组织方案 |

### 典型问法（可直接照抄）

> **"做一个手持小家电外壳，要能注塑、要防摔，现在壁厚 1.2mm 摸着发软。帮我从选材料开始定方案，然后给结构改法，最后列一份开模前的缺陷风险清单——我要拿着这份去模具厂评审。"**

命中：`cmf-system` → `product-structure-liubaoshun` → `product-injection-defects`（路由会同时带上 `ergonomics-ding-yulan` 查握持尺寸）

## 四、路 C：要一个证据 —— 验证链路

**路 C 的核心主张**：能不能用，**测出来**才算数；讨论出来的不算。

### C-0 为什么必须三个技能接力

| 只查一个 | 会缺什么 |
|---|---|
| 只查 `usability-testing` | 有测试流程，但**不知道该测谁**（普通用户？边界人群？） |
| 只查 `user-research-methods` | 知道该找几个用户，但**没有任务场景、主持禁语、严重度评级** |
| 只查 `inclusive-accessibility-design` | 知道排除了多少人，但**没有实测手段**，结论只能停在估算 |

**三环缺一，结论都不可用于决策。**

### C-1 第一环：选择层 —— 该不该测、测谁、几个

**技能**：`user-research-methods`

| 要看什么 | 具体节 | 拿到什么产出 |
|---|---|---|
| **该不该测** | ch01 §1.2 方法谱系五维、§1.3 设计五阶段 | 判断"这个问题属验证类还是探索类"，以及**当前处在哪一阶段**（阶段错了，方法再好也白做） |
| **测几个** | **ch06 §6.2（Goodman 样本量清单）、§6.3（UMoD 对照）、§6.5（没有数字时的四条替代判据）** | **具体人数**（含两书口径并列）+ 没有数字时的替代判据 |
| **测哪类人** | ch06 §6.4 矩阵设计（让每个格子都有人） | 被试矩阵（人群 × 熟练度） |
| **验证类方法的定位** | ch09 §9.3（**只写"什么时候选它"，不写怎么做**） | 决定"用可用性测试 / 木马法 / RITE / 并行原型 / 快速约会 / 启发式评估"中的哪一个 |
| **测完怎么分析** | ch07 §7.2 亲和图、§7.3 内容分析、§7.4 KJ 法、§7.5 主题网络、§7.6 三角验证 | 逐字稿 → 聚类 → 主题 → 三角验证后的发现 |

> **★ 为什么这一环必须排第一**：跳过它，最常见的后果是拿"**5 个被试够了**"当停止理由 ——
> 而 ch06 §6.5 给的是"**每人群格子 4–5 人**"，不是总数 5 人。

**产出**：一份**研究设计决定**
```
测不测 → 测什么类型（形成性/总结性/验证性/比较）
      → 测几轮（user-research-methods ch09 §9.4 RITE / §9.5 并行原型）
      → 每格几个被试（user-research-methods ch06 §6.5）
      → 人群矩阵（user-research-methods ch06 §6.4）
```

### C-2 第二环：执行层 —— 怎么测

**技能**：`usability-testing`

| 要看什么 | 具体节 | 拿到什么产出 |
|---|---|---|
| **测哪种** | ch03 §3.1（三个变量决定类型）、§3.2 探索/形成、§3.3 评估/总结、§3.4 验证、§3.5 比较 | 测试类型定名（**由变量定，不由名字定**） |
| **写计划** | ch05 §5.2 计划的九个组成部分 | 测试计划（九节齐全） |
| **写任务** | ch05 §5.3 任务清单（内部版）、**§5.5 任务场景（给被试看的版本）** | 两份任务文档（**内部版会泄题，不能给被试**） |
| **怎么问** | **ch05 §5.4 出声思维三种变体**、ch04（主持人技巧、禁语） | 主持脚本 + 禁语清单 |
| **被试怎么来** | ch06 §6.3 操作化定义、§6.6 筛选问卷、§6.7 招募渠道与两个陷阱、§6.8 筛选访谈 | 可发出的筛选问卷 |
| **先小跑一遍** | ch05 §5.6 试点测试（Pilot） | 试点报告（改掉任务歧义） |
| **测后转四次** | ch08 §8.2 发现汇总、§8.3 什么算一条"发现"、§8.4/§8.5 严重度（**Rubin 与 Barnum 两套并列**）、§8.6 报告结构与篇幅、§8.7 复测与迭代 | 发现清单 → 严重度评级 → 测试报告 → 迭代建议 |
| **跨技能接口** | **ch05 §5.10 把诺曼七原则翻译成测试任务** | 预期缺陷清单 → 可观察场景（防止"任务里写了界面字面"） |

> **★ 严重度有两套口径（Rubin / Barnum），方向相反，引用必须标方向。** 见 `usability-testing` ch08 §8.4 与 §8.5。

**产出**：一份**可交付的测试报告**
```
测试类型 → 计划（九节）→ 任务清单 + 任务场景 → 主持脚本
→ 筛选问卷 → 试点 → 发现清单 → 严重度评级 → 报告 → 迭代建议
```

### C-3 第三环：覆盖层 —— 谁被漏掉了、漏掉多少人

**技能**：`inclusive-accessibility-design`

| 要看什么 | 具体节 | 拿到什么产出 |
|---|---|---|
| **谁被排除** | ch02（能力谱七轴 → 三轴、用户金字塔十级 × 人口百分比）、ch03（需求性 vs 设计性排除、WINIT 五层） | 被排除人群清单（按轴、按严重度） |
| **排除多少人** | **ch04 §4.2 四步评估法**、§4.3 专家评估表怎么填、**§4.4 实测排除率**、§4.5 尺寸/力怎么算 | **一个百分比**（可写进评审结论） |
| **多轴耦合** | ch04 §4.6 多重计数（气泡图与耦合区） | 去重后的排除率（**否则同一批人被数两次**） |
| **方法选谁** | ch06 §6.1–§6.7（Systematic / 观察访谈 / 用户试验与问卷 / 检查表 / 模拟 / 专家评审）、**§6.9 专家评审 + 排除审计的组合** | 选定的评估方法 + 组合方案 |
| **模拟工具** | ch07（模拟工具的标定；原书自认含主观性） | 模拟方案与其可信度边界 |
| **极端用户** | ch08（为什么找极端用户能反推主流） | 极端用户名单（作为边界被试） |

> **★ ch04 §4.4 是这套技能里唯一能给你"排除率数字"的地方。** 评审时能说"这个设计排除了约 X% 的人"，
> 才有否决权；只说"要考虑无障碍"没有。

**产出**：一份**覆盖审计**
```
被排除人群（按轴）→ 四步评估 → 排除率百分比 → 去重 → 边界被试名单
```

### C-4 三环的交接点（关键，别漏）

| 交接 | 从 | 到 | 交什么 |
|---|---|---|---|
| ① | `user-research-methods` ch06 §6.4 矩阵 | `usability-testing` ch06 §6.3 操作化定义 | 人群矩阵 → 可筛条件 |
| ② | `inclusive-accessibility-design` ch04 §4.4 排除率 | `usability-testing` ch06 §6.4 矩阵 | 排除率高的人群 → 矩阵必须有的格子 |
| ③ | `inclusive-accessibility-design` ch08 极端用户 | `usability-testing` ch06 §6.7 招募渠道 | 极端用户名单 → 特殊招募渠道 |
| ④ | `usability-testing` ch05 §5.10 | `design-psychology-norman` 七原则 | 七原则 → 预期缺陷 → 可观察场景 |

### 典型问法（可直接照抄）

> **"我这版原型要过一次可用性测试，但我不想只测普通用户——请先判断该测几个、每类人几个，然后给一份能直接发的筛选问卷和任务脚本，最后告诉我这版设计大概把多少人排除在外、这个数字怎么算出来的。测完要一份带严重度评级的报告。"**

命中：`user-research-methods`（几个/测谁）→ `usability-testing`（问卷/任务/报告）→ `inclusive-accessibility-design`（排除率）

## 五、路 C 之外的补充路径

前面只讲了三条主路。以下四类问题不属于任何一条主路，但实际很常遇到。

### 补充 1：只问一个数（单点查证）

**特征**：不要结论、不要流程，只要一个准确数值或条文号。

| 你要的 | 查谁 | 看哪节 |
|---|---|---|
| P5/P50/P95 的人体毫米数 | `ergonomics-ding-yulan` | ch02（人体尺寸数据，GB 10000—1988 原始表） |
| 作业面高度该多高 | `ergonomics-ding-yulan` | ch08 §8.3b（表 8-4 坐姿作业面高度）、§8.3b.1（肘下 5–10 cm） |
| 坐姿/站姿可及范围 | `ergonomics-ding-yulan` | ch08 §8.3b.1（坐姿抓握男 65/女 58 cm；站姿 110–165 cm、±46 cm） |
| 无障碍条文级别与阈值 | `accessibility-standards` | ch01（WCAG 2.1 新增 17 条）、ch02（2.2 新增 9 条）、ch04（EN 301 549 第 8 章硬件数值） |
| 对比度要求 | `web-accessibility-cn` | ch07（4.5:1 / 7:1 / 3:1 与灰度检验法） |
| 光泽等级与反射率 | `cmf-system` | ch05（光泽六级 0–100%） |
| 折弯系数 / K 因子 | `solidworks-2025-mechanical` | 钣金章 |

**典型问法**：
> **"别给我方法论。直接告诉我：操作台面高度按人机工程该多少，男性女性分别多少，出处哪一章。"**

### 补充 2：用标准做采购或验收（合规路径）

**特征**：要的是一份**可验收的规格**，不是设计建议。

```
accessibility-standards（条文与级别）→ web-accessibility-cn（中文落地与用户角色）→ inclusive-accessibility-design（覆盖多少人）
```

| 环节 | 看哪节 | 产出 |
|---|---|---|
| 条文与阈值 | `accessibility-standards` ch04（EN 301 549 第 8 章硬件尺寸与力值）、ch08（三版 87 条对照 + 20 行实体产品验收判据） | shall/should 之分 + 可采购条款 |
| 中文语境 | `web-accessibility-cn` ch01–ch02（8 个中文用户角色、可访问性方程） | 中文用户场景 |
| 覆盖人群 | `inclusive-accessibility-design` ch04 §4.4 | 排除率（用于论证投入必要性） |

**典型问法**：
> **"我要给一个自助终端写采购验收条款，无障碍部分必须能写进合同。给我 WCAG 与 EN 301 549 里适用于实体设备的强制项（shall 级别），并标出各自的条目号和阈值。"**

> **注意**：`accessibility-standards` 明确标注了 EN 17161、ISO 21542、GB/T 37668 正文与中国《无障碍环境建设法》条文的获取状态与留白 —— **引用前先看它的"已知空白"**。

### 补充 3：只做造型诊断（不进入制造）

**特征**：产品还没定，要先判断"这个形态对不对/好不好看"。

```
product-design-styling-dabbs（造型语言）→ visual-dynamics-industrial-design（力感诊断）→ design-elements-hannah（形体组织）
```

**反向用法（诊断为主）**：如果已经有形态、只要判断别扭在哪，直接 `visual-dynamics-industrial-design` ch01–ch02（F 假设、倒叙分析），再回 `design-elements-hannah` 查比例。

**典型问法**：
> **"这个模型我看着别扭但说不清哪里。用视觉动力的方法倒推：是力感失衡还是比例问题？给出具体位置，不要只说'不够协调'。"**

### 补充 4：跨书冲突裁决（两个技能给了不同数）

**特征**：同一个问题，两本书给的数字或口径不一致，你不知道该信哪个。

本项目已实证的冲突点及处理原则：

| 冲突 | 涉及 | 处理 |
|---|---|---|
| 严重度评级方向相反 | `usability-testing` ch08 §8.4（Rubin，4 = 最重）vs §8.5（Barnum） | **引用必须标方向**，不可混用 |
| 被试数口径 | `user-research-methods` ch06 §6.2（Goodman）vs §6.3（UMoD） | **两书并列给出**，取保守值用于正式测试 |
| 页码口径 | 各书不同（书内页 / PDF 索引 / EPUB 无页码） | 见 `design-methodology-liuguanzong/references/PAGE-CITATION-CONVENTION.md`；**跨书禁止混用同一页码** |
| 材料主力位 | `cmf-system`（选什么）vs SW（软件里怎么设） | 见本文§零陷阱表 |

**典型问法**：
> **"这两本书对严重度的评级方向不一样，我写报告该按哪套？如果要同时引用，怎么写才不混淆？"**

---

## 六、三条例问法对照（可直接照抄）

| 路 | 问法 |
|---|---|
| **A（要结论）** | "这个手柄用户说握着难受。别急着改模型 —— 先说清三件事：按人机工程握持直径该多少（P5–P95 覆盖到哪）、从视觉构成和力感上看问题出在哪、最后在 SOLIDWORKS 里怎么改形并接顺。三层都给，从'为什么错'开始。" |
| **B（要产品）** | "做一个手持小家电外壳，要能注塑、要防摔，现在壁厚 1.2mm 摸着发软。帮我从选材料开始定方案，然后给结构改法，最后列一份开模前的缺陷风险清单 —— 我要拿着这份去模具厂评审。" |
| **C（要证据）** | "我这版原型要过一次可用性测试，但我不想只测普通用户 —— 请先判断该测几个、每类人几个，然后给一份能直接发的筛选问卷和任务脚本，最后告诉我这版设计大概把多少人排除在外、这个数字怎么算出来的。测完要一份带严重度评级的报告。" |
| *补充2（要验收）* | "我要给一个自助终端写采购验收条款，无障碍部分必须能写进合同。给我 WCAG 与 EN 301 549 里适用于实体设备的强制项（shall 级别），并标出各自的条目号和阈值。" |

**这三个（四个）问法的共同点**：都不是"XX 是什么"，
而是 **"目标 + 约束 + 现状 + 要什么形式的产出"**。

---

## 七、反面清单：这样问拿不到东西

| 问法 | 为什么不行 |
|---|---|
| "产品设计怎么做" | 命中太多，只能回方法论层，给不出数值 |
| "这个好看吗" | 没有约束（给谁用、什么工艺、什么价位），无法定位 |
| "帮我改一下" | 没说改的依据，只能凭印象 |
| "无障碍要注意什么" | 没有"排除多少人"这个量化目标，评审时无法否决 |

> **★ 一句话：问法里带"目标 + 约束 + 产出形式"，路由就能给到节号级的具体判据。**
