## 18.1 ★★★★★ Apply（应用变换）—— 为什么必须做

> **原文（`apply.xhtml`）**：
> 「**这些操作让你对选中的物体应用若干变换。
> 物体的变换坐标被转移到"物体数据"上。
> 如果物体有层级后代，它也会把这些变换应用到它们的子物体上。**」
> 「**应用变换值本质上是"重置物体的位置/旋转/缩放的数值"，
> 同时在视觉上保持物体数据原位。
> 物体原点被移到全局原点，旋转被清零，缩放值被设为 1。**」

**★★★★★ 一句话：Apply = "把变换烘进几何，然后数值归零"。**

```
Apply 之前：
   物体（位置 5,0,0 / 缩放 2.0）
      └── 数据（一个 1×1×1 的立方体）

Apply 之后：
   物体（位置 0,0,0 / 缩放 1.0）
      └── 数据（一个 2×2×2 的立方体，且顶点已偏移）
★ 视觉上完全一样
```

> **★★★ 判据：Apply 不改变"看起来的样子"，只改变"数值记录方式"。**

### 18.1.1 ★★★★★ 最关键的警告（原文 Warning）

> **原文**：
> 「**虽然对骨架应用变换是受支持的，
> 但这不适用于它们的姿态位置、动画曲线或约束。
> **这个工具应该在"绑定与动画之前"使用。**」**

**★★★★★ 一条时序铁律**：

```
★ Apply Transform 必须在【绑定 / 动画】之前做
   ↓ 为什么
★ 因为骨架的姿态、动画曲线、约束都"依赖原始变换"
   ↓ 反过来做
★ 动过的动画会"跑偏"
```

> **★★★ 判据：Apply 只能"在项目早期"做，不能"在动画做完后"补。**
> **★ 这是不可逆的顺序错误。**

### 18.1.2 ★★★★★ 为什么"修改器与约束依赖变换"（原文关键句）

> **原文**：
> 「**对简单情况，你不会在 3D 视口或渲染输出里注意到任何差异，
> 但修改器与约束可能依赖物体的变换。**」

**★★★★★ 完整理解"为什么换算出错"**：

| 功能 | 依赖什么 | 不 Apply 的后果 |
|---|---|---|
| **★ Bevel 修改器** | **★ 世界尺度** | **★ 倒角宽度"看起来对但实际不对"** |
| **★ Solidify** | **★ 世界尺度** | **★ 厚度不均（随缩放变）** |
| **★ 雕刻笔刷** | **★ 半径按物体尺度** | **★ 笔刷"过大/过小"** |
| **★ 物理模拟** | **★ Blender 单位** | **★ 重力/速度全错** |
| **★ 布料/刚体** | **★ 同上** | **★ 同上** |
| **★ 纹理（Generated 坐标）** | **★ 包围盒** | **★ 贴图随缩放变形** |

> **★★★ 判据：Apply Scale 解决的是"工具把'物体缩放'当成了'几何尺寸'"的问题。**
> **★ 因为 Blender 很多算法读的是"世界尺度"，而缩放值会影响它。**

### 18.1.3 ★★★★ 四种 Apply 选项

> **原文**：
> 「**`Object → Apply → Location / Rotation / Scale / Rotation & Scale`（`Ctrl+A`）**
> 当运行 Apply Transform 时，`Adjust Last Operation` 面板让你选择要应用的变换组合。」**

| 选项 | 效果（原文） |
|---|---|
| **★ Location** | **「应用（设定）选区的位置。这会让 Blender 认为当前位置等同于每个平面上的 0，即选区不会移动，当前位置被视为"默认位置"。物体原点会被设为实际 (0,0,0)。」** |
| **★ Rotation** | 旋转清零 |
| **★ Scale** | **★ 缩放归 1（最常用）** |
| **★ Rotation & Scale** | **★ 最常用的组合**（保留位置） |

> **★★★ 判据：硬表面最常做的是 `Rotation & Scale`** ——
> **★ 因为它"保留位置（方便摆放）但清掉旋转与缩放（保证工具正常）"。**

**★★★★ 原文的另一句**：
> **「如果物体有层级后代，它也会把这些变换应用到它们的子物体上。」**
> **★★ 判据：Apply 会"传染给子物体"** ——
> **★ 所以要么先 Apply 再建层级，要么接受子物体也被 Apply。**

## 18.2 ★★★★★ Knife Project vs Bisect（两种"切割"的区别）

### 18.2.1 ★★★★★ Knife Project（投影切割）

> **原文（`knife_project.xhtml`）**：
> 「**Knife projection 是一个"非交互式"工具，
> 你可以用物体来"饼干模切"进网格，而不是手画线。
> 它的工作原理是：用编辑模式里"其他选中的物体"的轮廓，
> 沿视图轴切割网格，切割物轮廓内的结果几何会被选中。**」
> 「**轮廓可以是线框（wireframe）或边界边（即网格里未连接的边）。**」

**★★★★★ 一条必须知道的前提（原文 Note）**：
> **原文**：
> 「**基本体（primitives）是流形物体，没有线框或边界边。
> 以立方体为例，删除顶面会产生切割边。**
> **用 `Select Non-Manifold (Wire, Boundaries)` 会高亮出网格物体的切割边。**」

**★★★★★ 完整理解"什么能当切割器"**：

| 能当切割器 | 不能 |
|---|---|
| **★ 线框（Wireframe 修改器后）** | **★ 未处理的立方体**（流形，无边） |
| **★ 边界边（有洞的网格）** | **★ 封闭的实体** |
| **★ 曲线物体** | — |
| **★ 文字物体** | — |

> **★★★ 判据：Knife Project 的切割器必须"有边"（线框/边界）** ——
> **★ 所以要先把实体"删掉一个面"或"加 Wireframe 修改器"。**

**★★★★★ 正确的操作顺序（原文）**：
> **「1. 在物体模式，先选"切割物体"。**
> **2. 用 `Shift+LMB` 追加选择"被切物体"。**
> **3. 进入编辑模式，选 `Mesh → Knife Project`。」**

| 步 | 注意 |
|---|---|
| **★ 先选切割器** | **★ 最后选被切物体** |
| **★ 顺序不能反** | （与 `Ctrl+J`/`Ctrl+P` 一致：最后选的是"主体"） |
| **★ 进编辑模式后执行** | 不是物体模式 |

> **★★ 判据：又是"最后选中的是被作用的那个"** ——
> **★ 这是 Blender 贯穿全书的交互约定（ch10/ch16 都讲过）。**

**★★★★ `Cut Through` 选项**：
> **原文**：「**把切割投影穿透整个网格。**」
> **★ 不勾 → 只切"可见面"；勾 → 切穿整个物体。**

**★★★★ 一条实用 Hint（原文）**：
> **「用 3D 视口的视图对齐来调整投影轴。」**
> **★★ 判据：Knife Project 是"沿视图轴投影"，所以"你从哪个角度看"决定"切在哪"。**

### 18.2.2 ★★★★ Bisect（平面切割）

> **原文（`bisect.xhtml`，763 字符）**：
> **用一个平面"切开"网格。**

**★★★★★ Knife Project vs Bisect 完整对照**：

| 维度 | **Knife Project** | **Bisect** |
|---|---|---|
| **切割形状** | **★ 投影轮廓（任意形状）** | **★ 平面（一刀直切）** |
| **依赖** | **★ 视图轴（你从哪看）** | **★ 平面的位置与朝向** |
| **需要别的物体** | **★ 需要切割器物体** | **★ 不需要** |
| **典型用途** | **★ 用文字/曲线切开** | **★ 把物体"切一半"** |
| **交互** | **★ 非交互（一次性）** | **★ 有参数面板** |

> **★★★ 判据：**
> **要"按某个形状切"→ Knife Project；**
> **要"一刀平分"→ Bisect。**

**★★★★ 与 `blender-hard-surface` 的对应**：
> **★★ ch08 用 Knife Project 一次**（切车体细节）**；**
> **★ ch01–ch12 都没用 Bisect。**

## 18.3 ★★★★★ 贴图密度（Average Island Scale）

> **原文（`meshes/uv/editing.xhtml`）**：

### 18.3.1 ★★★★★ 问题：多岛 UV 的"密度不一致"

```
一个物体 UV 展开成 3 个岛
   ↓ 每个岛在 0–1 空间里"大小不同"
   ↓ 贴同一张 1024×1024 的图
★ 岛 A 占 500px → 清晰
★ 岛 B 占 100px → 模糊
```

**★★★★★ 这是"同一个材质在不同部件上清晰度不同"的原因** ——
> **★ 不是材质问题，是 UV 岛的比例问题。**

### 18.3.2 ★★★★★ 解法：`Average Island Scale`

> **原文（UV 编辑工具之一）**：
> **把所有 UV 岛的"每单位几何对应的 UV 面积"统一。**

| 操作 | 结果 |
|---|---|
| **★ `Average Island Scale`** | **★ 所有岛的"贴图密度"一致** |
| **★ 之后 `Pack Islands`** | **★ 再打包进 0–1（避免重叠）** |

**★★★★★ 正确顺序（关键）**：

```
① UV 展开（Smart UV Project / 标 Seam + Unwrap）
   ↓
② ★ Average Island Scale（统一密度）
   ↓
③ ★ Pack Islands（打包进 0–1）
   ↓
④ 贴图（现在各岛清晰度一致）
```

> **★★★ 判据：先"统一密度"再"打包"** ——
> **★ 顺序反了，"打包"会把比例又改乱。**

### 18.3.3 ★★★★ 与 `blender-hard-surface` 的对应

> **★★ ch06 讲 Smart UV Project 与 Box Mapping，但没讲 Average Island Scale**；
> **★ ch12 讲 UV Grid 验证，但没讲"密度一致"。**
> **★ 本章补上了这一步。**

| **hard-surface ch12** | UV Grid 验证拉伸 | **★ 多岛密度一致** |
