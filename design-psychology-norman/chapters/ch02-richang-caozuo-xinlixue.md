# 第 2 章：日常操作心理学

## Core Idea
人的行动可拆成**七个阶段**（目标 + 执行三步 + 评估三步）；日常操作困难绝大部分发生在**执行鸿沟**与**评估鸿沟**上——用户不知道怎么做，也不知道自己做成没有。

## Frameworks Introduced

- **采取行动的七个阶段**（贯穿全书的分析骨架）：
  1. **确定目标**
  2. **确定意图**
  3. **明确行动内容**（动作顺序）
  4. **执行**
  5. **感知外部世界状况**
  6. **解释外部世界状况**
  7. **评估行动结果**
  - 结构：**目标（1）** + **执行（2~4）** + **评估（5~7）**。
  - 关键区分：**目标**指要达到什么样的结果，通常表述得比较含糊；**意图**指达到该目标所需采取的某个具体动作，比目标明确，但未明确到可以控制行动的程度。从目标到意图再到动作顺序，是一条**逐步具体化**的链路。
  - When to use：任何一个"用户不会用"或"用错了"的案例，先定位问题卡在七个阶段的哪一步。
  - 重要限定（作者的严谨之处）：**行动可以从七个阶段中的任何一点开始**。人并不总是先定目标再逐步实施；目标通常不完善也很模糊，许多行动只是对外界事件的反应。多数行为无须经历全部阶段，大目标会被细分为小目标，主意图下面还有次意图。

- **执行与评估的鸿沟**（本书最著名的诊断框架）：
  - **执行鸿沟**：用户无法确定自己的操作与设备工作程序之间的关系，以及各种控制键的功能和使用方法。
  - **评估鸿沟**：用户很难通过图像、声音、亮度、设备工作状态来明确自己是否成功达到了目标。
  - 结论：用户在这两处遇到的困难，本质是卡在**匹配**与**反馈**两个环节。
  - When to use：给"操作困难"归因时，先判断是"不知道怎么做"（执行鸿沟）还是"不知道做成没有"（评估鸿沟）。
  - 配套：**用来辅助设计的行动七阶段**——把每一阶段对应到设计要素上（意图对应可选项的可见性、执行对应控制器的可及与匹配、评估对应状态反馈）。

- **心理模型（mental model）**：我们习惯对事物加以解释，这就形成了针对事物作用方式、事件发生过程和人类行为方式的概念模型。
  - 作用：有助于理解经历、预测行为结果、应对意料之外的情况。
  - 性质：**经常是根据零碎的事实构建而成的**，对事实来龙去脉只有肤浅理解，并依据某种通俗心理学形成看法，而这些因素或许并不存在。
  - 来源：取决于知识结构，**不论这些知识是真实的还是想像中的，是粗浅的还是精深的**。
  - 后果分级：错误的心理模型导致日常受挫（调不好冰箱温度）；若对工厂或飞机上的复杂设备形成错误模型，**后果将不堪设想**。

## Key Concepts

- **人为差错的基本立场**：**如果某种错误有可能发生，就一定会有人犯这样的错误。** 设计人员必须考虑所有可能出现的错误，在设计时尽量降低差错发生的可能性或减轻差错所造成的不良后果；用户应当能够很快发现操作错误，并尽可能改正。
- **通俗物理学（亚里士多德式）**：运动物体需外力推动才能持续运动——虽被牛顿推翻，却**合理地描述了真实世界中观察到的现象**（因为真实环境有阻力与空气）。这类错误观念听起来很有道理。
- **错误归因**：一种状况紧接在一个动作后发生，人们就认定该动作是原因。同事抱怨"每次一连图书馆书目就死机，肯定是图书馆的错"，实际是**电源烧坏了**。
- **电冰箱的困惑**：两个控制钮分别标着"冷藏""冷冻"，但实际调温需要两钮联动，且需 24 小时工作状态才能稳定；用户无法从物品本身看出操作原理。
- **执行三阶段的内在性**：动作顺序"仍旧属于心理活动阶段，必须加以执行，才能在外部世界产生效果"。

## Mental Models

- **Use 七阶段 when 拆解任何一个操作失败案例**：逐阶段问"目标清楚吗？意图明确吗？动作能做吗？结果看得见吗？看得懂吗？能判断成功与否吗？"
- **Think of 两个鸿沟 as 两类抱怨**："我不知道该按哪个"= 执行鸿沟；"我不知道按对了没有"= 评估鸿沟。
- **Use「错误必然会发生」when 做设计假设**：不要假设用户会正确使用，而要假设有人一定会犯这个错，然后让错误可发现、可纠正、损失可控。
- **Treat 心理模型 as 用户自建的解释**：用户不会等你的说明书，他会用零碎事实自己拼一个；设计的任务是通过系统表象去引导这个拼装过程。
- **Use 通俗物理学 when 解释"用户为什么会错"**：错的是心理模型与真实机制不符，而不是用户的智力。

## Anti-patterns

- **让用户把设计缺陷归咎于自己**：用户出错后"不是试图隐瞒错误就是责怪自己'太笨'或'手脚不灵活'"，甚至像秘书那样**不向上汇报**——因为手册上写着，所以默认是自己没看仔细。这是最有害的反模式：它同时掩盖了问题。
- **同类功能却无区分线索**：`Return` 键与 `Enter` 键"功能相似、位置接近"，快速打字时不加思考就会误按，导致丢失前几分钟的输入。
- **用无声运转掩盖状态**：早期文字处理器不显示操作结果，用户以为没生效就**不断重复键入指令**，造成更多麻烦。
- **以"用户手册写了"作为免责依据**：设计人员回应"你没看手册吗？"，而秘书们的实际行为是出错后自责——手册无法替代设计。
- **忽略不熟悉环境下的认知负荷**：书中引用的棒球题实验里，刚学过牛顿物理的高中生仅 20% 答对，错误观念并不会因为"讲过一遍"而消失。

## Worked Example

**温度调节器：两种通俗理论 vs 实际机制**

问题：屋子很冷，想尽快暖和起来，是否应把温度调节器开到最大值？

1. **用户的两种通俗理论**：
   - **定时理论**：温度调节器只控制**运行时间**——调得越高，系统作用时间越长；调到最高就能持续不停运转。
   - **量性理论**：温度调节器控制**冷暖空气的流量**——调到极限值就能迅速达到最大制冷/加热效果。
2. **实际机制**：温度调节装置**仅起开关作用**——要么全开，要么关闭，没有半开半关；温度达到设定值就自动关闭。所以**调到最高并不会更快达到所需温度**。
3. **为什么会形成错误模型**：设计使用户无法知道正确的操作方法；在没有外部信息的条件下，人们就凭想像设想它是如何运作的，"只要他们的心理模型能够用来解释所观察到的事实"就被接受了。
4. **设计教训**：这个案例真正要说明的是——**并非只有某些人才会形成错误观念，人人都在用心理模型解释观察到的一切**。若设计能显示当前状态（加热中／已停止）与目标温度，用户的模型就会自动被校正。

## Key Takeaways

1. 行动 = 目标 + 执行（意图、动作顺序、执行）+ 评估（感知、解释、评估），共七个阶段。
2. 目标是"要达到什么结果"（含糊），意图是"采取哪个具体动作"（较明确），两者不可混为一谈。
3. 用户的两类困难：**执行鸿沟**（不知道怎么做）与**评估鸿沟**（不知道做成没有），分别对应匹配与反馈的缺失。
4. 设计假设应当是"**如果某种错误有可能发生，就一定会有人犯**"。
5. 用户出错时的自责与隐瞒会掩盖设计问题，是最需要警惕的信号。
6. 人人都在用心理模型解释世界，模型错误的责任在信息与设计，不在人的智力。
7. 对复杂设备而言，错误的心理模型后果可能不堪设想，因此系统表象必须可靠。
