# 第 3 章：头脑中的知识与外界知识

## Core Idea
完成任务所需的知识有两种存放处——**头脑中**与**外界**；两者在可提取性、学习成本、使用效率上各有优劣，好设计让二者**互补**，而不是逼用户把一切都背下来。

## Frameworks Introduced

- **知识两分框架（本章主线）**：
  - **储存于外部世界的知识（信息）**：一旦完成任务所需的信息在外界唾手可得，**学习这些信息的必要性就大幅度降低**。
    - 例：普通硬币的知识我们其实很缺乏，但仍能辨别不同硬币；打字员未必默记键盘表，键上标注着字母即可上手。
  - **储存于头脑中的知识**：需要先学习才能存进去，需要付出相当多的努力，但一旦内化就**高效、快速**。
  - When to use：设计时决定"这条信息该印在产品上，还是该要求用户记住"。
  - 关键推论：**人们把知识储存在头脑中的精确程度，只需精确到可以维持工作质量的程度**——这就是为什么人们在各自环境中运转自如，却描述不清自己在做什么（能在陌生城市旅游，却说不清旅游路线）。

- **外界知识 vs 头脑中知识的权衡表（原书图 3-5）**：

| 特性 | 外界知识 | 头脑中的知识 |
|---|---|---|
| **可提取性** | 可以看到或听到 | 不易提取，需在记忆中搜寻或提醒 |
| **学习** | 不需要学习，以解释替代学习；解释难易取决于自然匹配和限制因素的使用程度 | 需要学习，有时需付出大量时间和精力；若材料有结构或有好的概念模型，可简化学习 |
| **使用效率** | 需要一个找寻和解释的过程，速度比较慢 | 效率很高 |
| **易用性** | 高 | 低 |
| **美观性** | 可能不美观；储存信息量太大就会凌乱，美观与否取决于设计人员能力 | 看不见，本身不存在美观问题；设计人员可获得更多空间专注于外观 |

  - 结论：**鱼和熊掌不可兼得**——从外界知识获益，就意味着放弃头脑中知识能提供的某些好处。
  - 稳定性差异：外界知识学起来容易但**用起来很难**，作用很大程度上依赖它是否在物质世界持续存在——**环境一旦变化，外界知识就会随之改变**；而头脑中的知识不受环境改变影响。

- **两类知识的类型划分**：
  - **陈述性知识（declarative knowledge）**：各类事实和规则（"红灯亮了要停车"）。**易用文字表达，也易于传授**。
  - **程序性知识（procedural knowledge）**：让人知道如何演奏乐器、如何在冰面上把爆胎的车平稳停住、如何在说"frightening witches"时正确移动舌头。**难以甚至不可能用文字表述**，因此很难用言语教授——**最好的教法是示范，最好的学法是练习**；这类知识大多是**下意识的**。

## Key Concepts

- **自我提醒功能**：储存于外界的知识**具有自我提醒的功能**，它帮助我们回忆起容易遗忘的内容（把要做的事写在纸条上、把物品放在特定位置）。
- **用解释替代学习**：外界知识最大的价值是**不需要学习**——用户通过"看"和"解释"就能获得所需信息。
- **解释难易的决定因素**：取决于对**自然匹配和限制因素**的使用程度（呼应第 1、4 章）。
- **行为的精确性与知识的不精确性**：人的行为可以是精确的，而支撑它的知识却不必精确——因为大部分信息可以在环境中随时提取。
- **学习成本的场景依赖**：偶尔打印少量文字，靠外界知识足矣；要定期打印大量材料，就必须上课、练盲打、把键盘知识存进记忆。
- **典型的外界知识设计**：键盘上的字母、控制器上的指示灯和标记、工业设备上提醒用户的各种辅助记忆设计。

## Mental Models

- **Use「环境里能找到就不必背」when 决定信息放在哪**：凡是能在环境中稳定获得的信息，就不必要求用户学习。
- **Use「效率换学习」when 追求高频操作的熟练度**：想让操作更快更省脑力，就必须让用户把知识内化——这需要练习时间。
- **Think of 外界知识 as 有自我提醒能力的备忘**：它的价值在"一直在那里"，风险也在"环境一变它就没了"。
- **Use 陈述性/程序性 when 选择教学方式**：能用文字讲清的就写清楚，不能讲清的就**示范 + 练习**。
- **Treat 知识的精确度 as 可调参数**：只需精确到能维持工作质量即可，不必追求完整记忆。

## Anti-patterns

- **把本该放在环境里的知识全部要求用户记住**：这会把使用效率的收益，建立在学习成本的巨大代价上。
- **依赖外界知识却不保证其稳定性**：环境一变（设计改版、布局调整、贴纸脱落），依赖它的能力立刻失效。
- **要求用户拥有精确的知识才能正确操作**：书中明言人们的行为精确而知识不精确；靠"记住规则"的产品必然出错。
- **用文字去教程序性知识**：程序性知识"难以、甚至不可能用文字表述清楚"，只写说明书而不给示范与练习是徒劳的。
- **把信息量大等同于帮助**：外界信息储存量太大就会**凌乱**，反而破坏美观与可用性。

## Worked Example

**一辆借来的车：为什么"提示"应当长在物品上**

朋友把车借给作者时留了一张字条："我忘了告诉你，拔钥匙前，需把变速杆挂在倒车挡。"

1. **信息归属判断**：这条信息（拔钥匙前挂倒挡）**在车内无处可寻**——从这辆车的设计上根本找不到任何该操作方法的提示，因此它**只能储存于人的头脑中**。
2. **后果推演**：如果使用者缺乏这一知识，**车钥匙就会永远插在点火装置上**。作者的原话是"如果没有看见字条，我根本不会知道这一点"。
3. **对照本章框架**：字条是典型的"外界知识"——学起来容易（读一眼即可）、用起来却要依赖它**持续存在**（纸条丢了、换了驾驶者就失效），且不美观。
4. **设计上的正确解法**：把这条知识**写进物品本身**（例如让空挡位置无法拔钥匙，或让倒挡成为唯一可拔钥匙的位置）。这样知识就从"必须记住"变成"环境强制给出"，与第 5 章的**强迫性功能**是同一条思路。

## Key Takeaways

1. 完成任务的知识可存于**头脑中**或**外界**；外界知识降低学习成本，头脑中知识提高使用效率。
2. 两者是**权衡**关系：外界知识可提取、易用，但慢且可能凌乱；头脑中知识高效，但需学习、不美观。
3. 外界知识的致命弱点是**环境一变就失效**；头脑中知识不受环境影响。
4. 用户行为的精确性不要求知识的精确性——**只需精确到能维持工作质量**。
5. **陈述性知识**可文字传授；**程序性知识**只能靠示范与练习。
6. 外界知识有**自我提醒**功能，这是它不可替代的价值。
7. 设计应当容许用户在外界知识与头脑中知识之间**视情况选择和互补**。
