# 速查表（Cheatsheet）

## 决策规则

| 情形 | 决定 |
|---|---|
| 用户不懂操作原理 | 先补**概念模型**（操作原理可见 + 动作符合模型 + 状态反映模型），而非补说明书 |
| 用户不知道该动哪里 | 补**可视性** + **自然信号**；相关零件必须显而易见 |
| 用户不确定操作生效没有 | 补**反馈**：立即、明显，且看得到"与前一状态相比的变化" |
| 一排控制器对应一排对象 | 用**匹配**：控制器排布与受控对象排布同构 |
| 想让"装错"变成不可能 | 叠加**四类限制因素**：物理结构 / 语意 / 文化 / 逻辑 |
| 限制因素设计了却仍出错 | 检查它是否**可见、可解释**（挡风玻璃仍装反即是反例） |
| 任务需要的信息可在环境中获得 | 放进**外界知识**，用解释替代学习 |
| 操作要求高频、快速 | 允许并鼓励用户把知识**内化到头脑** |
| 信息量很大却贴满界面 | 外界信息太多会**凌乱**，应精简（美观也是设计指标） |
| 要判断一个差错的性质 | 目标错 = **错误**；目标对而执行错 = **失误** |
| 差错后果不可接受 | 用**强迫性功能**让错误做不到，而非发警报 |
| 操作不可撤销 | **特意增加其操作难度** |
| 操作可撤销 | 提供撤销 |
| 出现差错 | 不惩罚、不动怒，但**也不能置之不理** |
| 只想用警报防错 | 先评估三条失效原因：会故障、分不清故意、太多而被忽略 |
| 需求方要求加功能 | 认清"加功能 → 隐藏操作信息 → 违背全部设计原则"，替用户把关 |
| 判断设计能否被理解 | 复述给用户听：**简单物品若需要图解说明，设计就失败了** |
| 想验证"别人是否也会卡住" | **与真实用户交流 + 让用户试用** |
| 存在"不该操作的人" | **反向应用**易用性原则，加大难度（只挡不该用的人） |
| 前六条原则都做不到 | 才用**标准化**兜底 |
| 判断是否在"自然演进"的轨道上 | 用**登山模型**：改一步感觉变好就继续，变坏就换方向 |

## 决策树

```
用户遇到操作困难，问题出在哪？
├─ "不知道该按哪个/怎么做"  → 执行鸿沟
│    ├─ 操作部位看不见      → 补可视性
│    ├─ 看不到部件对应关系  → 补匹配
│    └─ 看不出可能的动作范围→ 补预设用途/限制因素
└─ "不知道做成了没有"      → 评估鸿沟
     ├─ 没有即时反馈        → 补反馈
     ├─ 有反馈但看不懂      → 分离"状态显示"与"装饰"
     └─ 反馈延迟太长        → 缩短反馈周期（如冰箱需 24 h 才稳定=最坏情形）

出现了一次差错，该改人还是改设计？
├─ 目标本身错了  → 错误(mistakes) → 补信息、改教育、修正概念模型
└─ 目标对而执行错 → 失误(slips)  → 补限制因素/强迫性功能，别要求"更小心"
```

## 阈值与默认值

| 项 | 值／判据 |
|---|---|
| 完成概念模型的三个条件 | 操作原理显而易见；所有动作符合模型；可视部分反映当前状态 |
| 反馈的两条硬要求 | **立即**、**明显** |
| 失误的种类数 | 6 类 |
| 差错设计原则条数 | 4 条 |
| 限制因素种类数 | 4 类 |
| 化繁为简原则条数 | 7 条 |
| 行动阶段数 | 7 个（目标 1 + 执行 3 + 评估 3） |
| 心理模型的三个方面 | 设计模型、用户模型、系统表象 |
| 日用品数量级 | 一个成年人可能要接触约 **3 万件**不同物品 |
| 学习成本标尺 | 每件 1 分钟 × 2 万件 = **333 小时**（约 8 个工作周） |
| 自然演进的适用条件 | 时间充足 + 物品简单 |
| 冰箱调温的稳定时间 | **24 小时** |
| 公共水龙头计时器档位 | 出水持续 **5~10 秒** |
| 乐高摩托车零件数 | **13 个**（含 2 个可互换方块、3 个同形异色方块） |
| 文字处理系统的说明书代价 | **340 页**参考资料 + **150 页**初学者指南 |

## 识别信号

- 用户说"我太笨""手脚不灵活" → **设计问题**，不是人的问题（且这类自责会被隐瞒）。
- 用户不看说明书就上手 → 说明本该靠预设用途解决，而不是靠手册。
- 简单物品却需要长篇图解 → 设计已失败。
- 同类功能、位置接近、无区分线索（`Return` vs `Enter`）→ 高失误风险。
- 产品"获过设计奖"却让人不会用 → 奖项把美观置于可用性之上的信号。
- 操作后毫无声响或显示 → 用户会**重复键入指令**，问题被放大。
- 报警器响而用户无视 → 警报已被噪声化，防错已失效。
- 新产品不继承旧产品的操作方式 → 用户既有知识被清零。
- 同一控制器承担两种功能却无提示（轻按/长按）→ 必然造成误操作。
- 关键部位"看不到也摸不到"却服务于安全目的 → 这是**有意为之**，不要贸然"修正"为高易用。
