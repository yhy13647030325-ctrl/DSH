- **核心动作**：实地观察用户行为，发现真实问题

| 例：上班族 | 例：办公室 | 例：每隔一段时间调整坐姿 | 例：固定高度无法适应不同任务 |

## 第二步：重在分析（理解问题）

- **核心动作**：深入分析现象背后的原因和需求
- **输出**：需求分析报告

| 现象 | 表层原因 | 深层需求 |
|------|---------|---------|
| 例：频繁调整坐姿 | 例：单一姿态不适 | 例：需要多姿态切换的支撑 |

## 第三步：精于归纳（提炼规律）

- **核心动作**：从具体案例中提炼共性和规律
- **输出**：设计原则、用户画像

| 归纳出的共性／规律 | 由此得到的设计原则 |
|------------------|------------------|
| 例：不同任务需要不同姿态 | 例：支撑方式应随任务可调 |

## 第六步：勤于评价（优化迭代）

- **核心动作**：持续评估和优化方案
- **输出**：评估报告、迭代方案

| 评价维度 | 判据来源 | 结论 | 下一轮迭代动作 |
|---------|---------|------|--------------|
| 合理性 | "合情合理"：既符合情感需求，又符合客观规律 | | |
| 情的满足 | 人的动机、目的、情感、需求 | | |
| 理的满足 | 知识、规律、客观条件 | | |
| 使用而非占有 | 设计应关注使用而非占有 | | |
| 全生命周期 | 作品→产品→商品→用品→废品 | | |
| 有限理性 | 在有限信息下寻求满意解而非最优解 | | |
