### 3. 事实纠错：两处键位（本轮最重要）

在运行中的 **Blender 5.1.2 GUI** 里读 keyconfig，纠正了流传多年的错误：

| 项 | 原有说法（错误） | **实测 5.1.2** | 改正处数 |
|---|---|---|---|
| **重算法线** | `Ctrl+N` 是"新版" | **`Shift+N`**（`mesh.normals_make_consistent`） | **12 处** |
| **合并顶点** | `Shift+W` | **`M` 菜单 → By Distance**；`Shift+W` 实为 **`transform.bend`（弯曲）** | **12 处** |
| **`Alt+S`** | 沿法线缩放 | **仅编辑模式**；物体模式为 `object.scale_clear`（清除缩放） | 补模式区分表 |

**为什会错**：原书（`blender-hard-surface` 的源）那么写，我照抄；2.92 手册又没列 Hotkey（`Merge by Distance` 只写 Menu）。
**两本交叉验证都缺位**，直到在 GUI 里实读才暴露。

**受影响的文件**：
```
blender-hard-surface/SKILL.md
blender-hard-surface/references/blender-shortcuts.md
blender-hard-surface/references/cheatsheet.md
blender-hard-surface/references/failure-modes.md
blender-hard-surface/chapters/ch03-fn-scar-details.md
blender-hard-surface/chapters/ch06-scifi-ship-texturing.md
blender-hard-surface/templates/project-plan.md
```

**复验方法**（必须在 GUI 里跑，后台模式只有 12 条 keymap_items）：
```python
import bpy
kc = bpy.context.window_manager.keyconfigs.active
def keys(op):
    return [(km.name, ("Ctrl+" if i.ctrl else "")+("Shift+" if i.shift else "")+i.type)
            for km in kc.keymaps for i in km.keymap_items if i.idname==op]
print(keys("mesh.normals_make_consistent"))  # [('Mesh','Shift+N'), ('Mesh','Ctrl+Shift+N')]
print(keys("mesh.remove_doubles"))           # []  ← 无快捷键
print(keys("transform.bend"))                # [('Mesh','Shift+W'), ...]
```

### 关键发现（据实汇报）

**① 原书是纯扫描 PDF，无文字层**

**这就是内容泛泛的根本原因**——不是提炼不够，是**原文没读完**。

全书**无任何标准公差代号**（H7/h6/IT 等级），仅术语表提及"基孔制/基轴制"。
p051 有完整的轴零件图公差标注（圆柱度 0.006、跳动 0.015 A-B、Ra1.6/3.2 等），

### manifest 机制设计要点

**为什么需要 manifest**：
脚本无法自动知道"某页是否真的读过"——
**只有人能声明"我读了哪几页"**。

所以 manifest 的 `read` 字段是**人的声明**，脚本负责**校验引用是否落在声明范围内**。

```json
{
  "book": "《产品结构设计》刘宝顺，中国建筑工业出版社，2005",
  "page_range": [9, 136],
  "read": [9, 10, 11, "...共 128 页"],
  "note": "p136 为参考文献页"
}
```

> **★ 这个设计承认了一个事实**：
> **"是否读过"不可自动验证，但"引用是否超出声明范围"可以。**
> 这把"诚实声明"变成"可审计"。

### 为什么值得单独记

这两次都是**工具误报**（共 964 个假 ERROR），不是文档有错。

> **误报比漏报更消耗信任**——一次假 ERROR 会让人开始怀疑所有 ERROR，
> 进而忽略真正的缺陷。所以规则本身必须先被验证。

### 教训 1：格式不统一会连带破坏"范围统计"

| | |
|---|---|
| **现象** | 用 `p(\d{3})` 统计范围 → [145,921]，报 **180 个假 ERROR**（`p11–69` 被判越界） |
| **根因** | 存在 `p11`（两位）写法，三位正则匹配不到 → 下限被算成 145 而非 11 |
| **做法** | 范围统计用 `p(\d{2,3})`；格式检查才用区分写法的正则 |
| **推广** | **只要两种写法共存，任何只认一种的统计代码都会漏数据** |

> **结论：统一格式不是美观问题，是数据正确性的前提。**

### 教训 2：元文档必须排除在单技能扫描之外

| | |
|---|---|
| **现象** | CHANGELOG 记了各技能页码（`p13–p207`）→ 报 **784 个假 ERROR** |
| **根因** | CHANGELOG 是元文档，引用的是**别的技能**的页码 |
| **做法** | 维护 `META_FILES` 集合；确需检查用 `--include-meta` |
| **推广** | **"记录内容"的文档与"被记录的内容"必须分层** |

> **判断标准**：这个文件是在**讲内容**，还是在**记录内容**？

**① 脚本头部 docstring**（`validate-page-citations.py` 第 60-140 行附近）

**1. 统一数字模式**
```python
_RE_CN = r"[一二三四五六七八九十]+"
_RE_AR = r"\d{1,2}"
NUM_PAT = rf"(?:{_RE_CN}|{_RE_AR})"      # 两写法全吃
RE_SEC_NUM_PREFIX = rf"(?:{NUM_PAT})\s*[、.．]"  # "一、"/"1、"/"1. "
```

def cn2int(s):
    if s.isdigit():          # 阿拉伯
        return int(s)
    return CN_NUM_REV.get(s) # 中文
```

def _keep_style(m):
    lead, old_num, tail = m.group(1), m.group(2), m.group(3)
    if old_num.isdigit():
        return f"{lead}{n}{tail}"      # 原来是阿拉伯 → 仍阿拉伯

## 2026-11-12 · 遗留①收尾：中文数字支持万/亿

### 背景

上一轮说"遗留① 中文算法覆盖到 9999"，但实测发现**它比记录的更严重**：

| 输入 | 上一版结果 | 应为 |
|---|---|---|
| `一万三千个技能` | **3000**（截成"三千"） | 13000 |
| `三万二个技能` | **2**（截成"二"） | 30002 |
| `一万个技能` | None | 10000 |

**最危险的是前两行**：它们**不返回 None，而是返回一个看似合理的错误数字**。
自检（"解析失败就 WARN"）**完全兜不住**——因为解析"成功"了。

> 这是本项目第三次遇到同类问题，且是**最隐蔽的一种**：
> 静默失效 → 静默跳过 → 到了这一层是**静默算错**。

### 修复内容

| # | 改动 |
|---|---|
| 1 | 单位表新增 `CN_SECTION = {"万": 10^4, "亿": 10^8}` |
| 2 | 正则从 `[一…十百千零〇两]` 扩到含 **万/亿** |
| 3 | `cn2int` 重写为**标准分节算法**（数字→pending，小单位→section，大单位→升格并入 total） |

### 算法与验证

```
十四         = 10 + 4                 = 14
一百零五     = 100 + 5                = 105
九千九百九十九 = 9000+900+90+9         = 9999
一万三千     = 10000 + 3000           = 13000
三万二       = 30000 + 2              = 30002
一亿二千万   = 10^8 + 2000*10^4       = 120000000
```

**25 个用例全部通过**（含 1..9999、万级、亿级、阿拉伯、异常输入）。

### ★ 修复过程中的两次错

**第一次**：直接加 万/亿 后，`九千九百九十九` 算出 **9009099**（section 累加逻辑写错）。

**第二次**：`一亿二千万` 算出 **1000020000000**——
     因为"万"分支错误地把已有 total 也乘了一遍。
     正确做法是：**万 → `total += section*10^4`（不乘 total）；亿 → `total = (total+section)*10^8`**。

> **教训**：中文数字的"分节"不是简单的乘加，
> **万和亿的层级不同**（万是节内单位，亿是更高层级）。
> 这类算法**必须用固定用例表逐条验证**，不能靠"看着差不多"。

### 端到端验证

**夹具**：`## 一、一万三千个技能` + 表 2 行

| 本版 | 解析为 **13000**，报 `标题声明「一万三千个技能」但速览表实际 2 行` ✓ |

| **不建议** | 上一版有"静默算错"缺陷 |

### 遗留（更新）

## 2026-11-12 · 遗留②收尾：裸量词规则

### 结论：`cn2int("万")` **报错（返回 None）**，不当成 10000

### 判断依据

**① 规范中文数词中，除「十」外都必须带前导数字**

正确写法：`一百`、`一千`、`一万`、`一亿`
单独一个「万」在数词里**不成词**。

**② 「十」是唯一例外，不能类推**

`十` 单独出现**是**标准写法（"十个" = 10）。这是中文数词固有规则，
不是可以自由放宽的实现选择。

**③ 若当成 10000，会重犯前面三类问题**

这正是本项目反复在修的同一个模式：

| 层次 | 表现 |
|---|---|
| 1 | 静默**失效**（超限返回 None，调用方跳过） |
| 2 | 静默**跳过**（正则不匹配，无人知） |
| 3 | 静默**算错**（"一万三千"→3000） |
| **4（本条）** | **静默算出看似合理的值**（"万"→10000） |

返回 None → 触发自检 → 变成**可见 WARN**。这才符合"宁可 WARN，不可静默"。

### 实现

| 位置 | 规则 |
|---|---|
| 小单位分支 | `百/千` 前无数字且未累计 → 返回 None |
| 大单位分支 | `万/亿` 前无数字且 `total==0` → 返回 None |
| 例外 | `十` 仍允许裸用（=10） |

> **注意 `total != 0` 的情况**：如"一万亿"里的"亿"，
> 前面已有 total=10000，此时裸"亿"是合法的（=10^12）。已正确保留。

### 验证

**裸量词（6 例）**
```

cn2int('百') = None   ✓
cn2int('千') = None   ✓
cn2int('万') = None   ✓
cn2int('亿') = None   ✓
cn2int('零') = None   ✓

**合法写法回归（21 例，0 失败）**
覆盖 1..9999、万级、亿级、复合（"十四万"/"一百二十万"），全部正确。

         应写成「一百」「一千」「一万」「一亿」（「十」除外，它可单独使用）

**提示是可操作的**：直接告诉用户该改成什么，而不只是说"解析失败"。

### 脚本增强

**问题**：ch08 含三本 SOLIDWORKS 书的 PDF 页码，刘宝顺的 manifest 把它们当成自己的页码 → **36 个假 ERROR**。

**解法**：manifest 加 `mixed_sources` 字段：

```json
"mixed_sources": {
  "note": "ch08 是跨书专题，内含其他书的 PDF 页码",
  "files": ["chapters/ch08-assembly-datum-tolerance-crossbook.md"],
  "other_books": {"战": "...", "2025": "...", "曲": "..."}
}
```

`validate-page-citations.py` 读取该字段，**跳过这些文件的页码扫描**。

> 这与之前"元文档排除"是同一类问题：
> **一个文件里的页码不一定属于本书**，必须能声明归属。
