### 2.2 三组"真重叠"（必须处理）

#### ★ 第一组：SOLIDWORKS 三本（0.84–0.91）

| 技能 | 章 | 定位（从内容实读） |
|---|---|---|
| **SW-实战** | 13 | **"怎么做出来"**（操作流程 + 特征选型） |
| **SW-曲面** | 7 | **"曲面怎么连续"**（G0–G3 / 缝合 / 主模型） |
| **SW-2025** | 14 | **"功能全览"**（含钣金/焊件/仿真/线路） |

> **★★★ 判据：三本不冲突，是"深度 / 专项 / 广度"三种切法。**
> **但**必须在使用时明确"先查哪本"**，否则会反复翻三本。

**建议的分工索引**：

| 问题 | 查哪本 |
|---|---|
| "这个特征怎么建" | **SW-实战** |
| "曲面接不顺怎么办" | **SW-曲面** |
| "2025 版有没有 XX 功能 / 这个参数什么意思" | **SW-2025** |

#### ★ 第二组：造型 × 视觉动力（0.83，24 主题）

| 维度 | 造型（Dabbs） | 视觉动力（李想） |
|---|---|---|
| **骨架** | **10 阶段流程**（轮廓→比例→形状→形态→线条→体积→表面→立体→颜色→材料） | **10 层理论**（快感奖励→F 定义→三种图示→冲突→生长约束→先天后天→分析修改→法向→三维形体→流动节奏） |
| **方法** | **"怎么做"**（每阶段有操作步骤 + 章节回顾清单） | **"为什么"**（每层有物理/生理推导） |
| **判据密度** | 2.65 | 3.82 |
| **可操作性** | **★★★★★**（10 阶段可直接照做） | ★★★（偏原理，需转化） |

> **★★★ 判据：这是"操作性 vs 解释性"的互补，不是重复。**
> **但两者都讲"比例/轮廓/形态/线条/表面/体积"** ——
> **★ 重叠的正是这 6 个造型维度。**

**建议的分工**：

| 场景 | 用哪本 |
|---|---|
| **接到造型任务，要按流程做** | **造型**（10 阶段） |
| **"这个形状为什么看着不舒服"** | **视觉动力**（诊断原理） |
| **要给客户解释设计理由** | **视觉动力**（有物理/进化依据） |
| **要检查有没有漏步骤** | **造型**（章节回顾清单） |

#### ★ 第三组：SW-2025 × 结构设计（0.75，24 主题）

| 维度 | SW-2025 | 结构设计 |
|---|---|---|
| **结构知识来源** | **软件功能**（怎么建模） | **真实产品**（为什么这样设计） |
| **典型判据** | "拔模斜度设多少度" | "为什么需要拔模斜度"（脱模） |
| **风险** | **★ 只学软件 → 会建模但不知对错** | **★ 只学结构 → 知道对错但建不出来** |

> **★★★ 判据：这两本是"原理 ↔ 实现"的一对，不能互相替代。**

### 2.3 六组"假重叠"（主题词撞车，实质不同）

> **为什么会出现假重叠**：矩阵按"词"统计，而不同书用同一词指不同对象。
> **例**："结构"在 SW 里指"特征树"，在结构设计里指"物理结构"；"安全"在人机里指"人因"，在结构设计里指"安全装置"。

| 配对 | 假重叠原因 |
|---|---|
| **设计史 × 造型（0.90）** | "设计师/企业"都是人物名，"审美"都是形容词，但**设计史讲"历史脉络"，造型讲"操作方法"** |
| **设计史 × 视觉动力（0.79）** | 都提"包豪斯/拉姆斯"，但**设计史讲贡献，视觉动力借其判据** |
| **BL-手册 × 造型（0.77）** | "比例/表面/体积"在 BL 里是"建模参数"，在造型里是"审美变量" |
| **BL-手册 × 注塑缺陷（0.76）** | "工艺参数"在 BL 里是"修改器参数"，在注塑里是"温度压力" |
| **SW-实战 × BL-手册（0.74）** | "建模操作"两本书都讲，但**软件完全不同** |
| **SW-实战 × 造型（0.74）** | "形状/表面"两本书都讲，但**一个是建模，一个是审美** |

> **★★★ 判据：13 个技能中，真正需要"合并或分工"的只有 3 组（§2.2）。**
> **其余 6 组高重叠是统计假象。**

## 五、结论与建议

### 5.1 三条结构判断

**① 13 个技能不是"13 个平行库"，是三层结构**

```
【原理层】design-psychology / design-elements / visual-dynamics / 设计史
   ↓ 提供"为什么"
【方法层】造型 / 人机工程 / 结构设计 / 注塑缺陷
   ↓ 提供"怎么做"
【工具层】SW ×3 / BL ×2
   ↓ 提供"用什么做"
```

> **★★★ 判据：查问题时先判断"要原理/方法/工具"，再进对应层。**
> **★ 直接跳到工具层，会"会建模但不知对错"。**

**② 三个"独占资产"必须保住**

| 资产 | 独占者 | 价值 |
|---|---|---|
| **人体尺寸硬数据** | **人机工程（唯一）** | 所有尺寸决策的唯一来源 |
| **设计史脉络** | **设计史（唯一）** | 唯一能答"这个风格从哪来" |
| **密封/运动机构** | **结构设计（唯一）** | 唯一能答"怎么动/怎么不漏" |

**③ 三组真重叠有明确分工，不必合并**

`SW×3` = 深度/专项/广度 · `造型×视觉动力` = 操作/解释 · `SW-2025×结构设计` = 实现/原理

### 5.2 五个建议动作（按优先级）

| 优先 | 动作 | 理由 |
|---|---|---|
| **P1** | **补"无障碍/包容性"** | **完全空白**，而人机工程有现成框架可扩展（百分位 → 超界人群） |
| **P1** | **补"用户研究方法"** | 总命中 1，而造型 ch01 已有"用户画像五问"的接口 |
| **P2** | **补"可用性测试"** | 设计心理有"七原则"，缺"怎么验" |
| **P2** | **补"CMF 系统"** | 造型有材料四问、视觉动力有色彩，缺"系统化 CMF 流程" |
| **P3** | **建"跨技能索引"** | 37 主题 × 13 技能矩阵已生成，应做成可查的路由表 |

### 5.3 一个已有的好消息

**`design-router` 已经存在**，但它目前的描述是"按问题性质分派"——
**建议用本报告的 37 主题矩阵升级它**，让它能回答：
- "这个问题该查哪一本？"（按主题 → 主力技能）
- "这个尺寸该查哪里？"（→ 人机工程，唯一）
- "这个风格从哪来？"（→ 设计史，唯一）

| **46** | **★★★★★ 无障碍不是"为少数人做的特殊设计"，是"为所有人的某个生命阶段做的设计"**（台阶旁坡道：轮椅/婴儿车/行李箱/拄拐老人都用） |
| **47** | **★★★★★ 三层次**：可及（加辅助）/ 通用（一物通用）/ 包容（承认差异+提供选择） |
| **48** | **★★★★★ 通用设计七原则**（Ron Mace, 1989）：公平使用 / 使用灵活 / 简单直观 / 信息可感知 / 容错 / 省力 / 尺寸与空间可及 |
| **49** | **★★★★★ 本书已覆盖七原则中的 6 条，唯一缺的是"系统整合"** |
| **50** | **★★★ 三类人群尺寸策略**：老年人（大字高对比+大按钮）/ 儿童（P5 定最低可达高度）/ 轮椅使用者（台面 750–800mm + 膝空间 ≥650mm + 侧向净空） |
| **51** | **★★★ `坐姿眼高` 与 `立姿眼高` 差约 300mm** → "可及"的核心是"双高度"或"可调高度" |
| **52** | **★★★★★ `可调` 是包容性设计的性价比之王**（一个可调范围覆盖 P5–P99，且不需为"特殊人群"单独设计一版） |

> **★★★★★ 判据（补足后最重要的一条）**：
> **无障碍不是"为少数人做的特殊设计"，是"为所有人的某个生命阶段做的设计"。**
> **★ 这不是道德要求，是数学事实**——每个人都会经历受伤、衰老、提重物、抱小孩的阶段。

### 7.3 P1-b：用户研究 / 可用性测试（补在"以用户为中心"章）

**为什么补在设计心理 ch07** —— 因为**第 7 章的核心主张"以用户为中心"必须靠方法落地**，
否则"七原则"只是口号。

**新增 8 条判据的核心**：

| # | 判据 |
|---|---|
| **35** | **★★★★★ `说的` < `记的` < `做的`**（偏好最低 / 回忆中低 / 观察最高）→ **能看就不问，能问就不猜** |
| **36** | **★★★★★ 五种方法按可靠性排序**：情境观察 / 可用性测试 / 深度访谈 / 问卷 / 焦点小组 |
| **37** | **★★ `焦点小组` 最被误用**（适合找话题，不适合验证方案）→ **验证必须一对一** |
| **38** | **★★★★★ 深度访谈"追问五次"**（前 3 层是合理化解释，第 4–5 层才是真实需求；追到"用户开始重复自己"就停） |
| **39** | **★★★★ 不要问"你想要什么功能"** → 要问"你上次遇到这个问题是什么时候？当时怎么处理的？" |
| **40** | **★★★★★ 可用性测试"五个必做"**：用户的话定任务 / 找 5 人 / 出声思考 / **不引导不打断** / 记录卡住点 |
| **41** | **★★★★★ `5 个人`就够**（85% 问题；与其 50 人做 1 次，不如 5 人做 10 轮） |
| **42** | **★★★★★ `不用的人`比`用的人`更有信息量**（三个陷阱：极端用户 / 熟人偏差 / 幸存者偏差） |

> **★★★★★ 判据（补足后最重要的一条）**：
> **`说的` < `记的` < `做的`** —— **能看就不问，能问就不猜。**
> **★ 这是所有用户研究方法的第一原则。**

> **★★★ 本节落点**：**七原则不是"检查表"，是"测试大纲"** ——
> 每条原则都能翻译成一个测试任务（如"为错误而设计"→ 故意制造断网/填错/误删场景测试）。
