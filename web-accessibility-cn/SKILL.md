## 核心框架速查

### 1. 三个方程（全书骨架，ch01）

| # | 方程 | 一句话 |
|---|---|---|
| ① | **人的能力 + 设计不当 = 网页的访问障碍**（p31） | **加法式**：两项可独立干预；设计团队只动得了第二项 |
| ② | **设计 + 可访问性 = 包容性设计**（p31） | 可访问性是**加数**，不是"最后加的" |
| ③ | **WCAG + 普适设计原则 + 设计性思维 = 人人都能使用的互联网**（p36） | **下限 / 方向 / 时机**，缺一不可 |

> **★ 推论**：**当①把障碍归到"设计不当"这一项时，改法就唯一了 —— 改设计，不是筛用户。**
> 「是产品本身产生了让人难以使用它的困难，而不是人自身的因素导致了这种困难」（p30）。

### 2. 九条原则（ch01 p32 = ch12 表 12-1）

### 3. 12 个锚点判据（贯穿全书，每条 ≥3 章出现）

| # | 判据 | 实体产品上的问法 |
|---|---|---|
| 1 | **越早越便宜 / 晚期只能妥协**（木梯·黄油） | 「这个改动是开模前定的，还是开模后加的？」 |
| 2 | **合规 ≠ 可用** | 「符合标准了，但用户真能做完吗？」 |
| 3 | **不能只靠一种通道** | 「转灰度/闭眼/静音，信息还在吗？」 |
| 4 | **反馈必须在使用它的那一刻、那一处** | 「用户操作到这一步时，这条说明看得见吗？」 |
| 5 | **内置才普及，外挂必经失效** | 「需要另配东西吗？几个前置条件？」 |
| 6 | **不做"功能更少的专用版"** | 「两版功能一样吗？」 |
| 7 | **结构/工艺决定，外观只能放大或掩盖** | 「把装饰全撕掉，还能用吗？」 |
| 8 | **要能被改造，不能只求一次做全** | 「用户想改它/适配它，能改哪儿？」 |
| 9 | **局部可见时仍要自解释** | 「遮住一半，剩下的能看懂吗？」 |
| 10 | **让用户能跳过、能退出、能撤销** | 「进得去，出得来吗？错了能回吗？」 |
| 11 | **为最受限的人做，顺带惠及多数**（坡道口） | 「顺带解决了哪些普通场景？」 |
| 12 | **没有专职警察，责任在所有能拍板的人** | 「谁有权因为可访问性推迟发布？」 |

> **★ 用法**：这 12 条不是"要背的清单"，是**评审时的 12 个提问** ——
> **每一条都能在 30 秒内对一份设计做出判断。**

### 5. 五种零成本验收法（不需要设备、不需要用户，5 分钟可做）

| # | 名称 | 做法 | 抓什么 | 出处 |
|---|---|---|---|---|
| **1** | **灰度检验** | 拍照转黑白 / 打印灰度 | 只靠色相的区分 | ch07 p141 |
| **2** | **纯文本模式** | 遮住所有装饰（颜色/图案/屏幕），只剩形状+位置+丝印+触感 | **只靠视觉的几乎全部缺陷** | ch11 p228 |
| **3** | **局部遮挡** | 遮住一半/一角，看剩余是否自解释 | 局部可见时失去结构 | ch03 p64 |
| **4** | **闭眼摸查** | 闭眼摸一遍，指出所有可操作件与当前状态 | 触觉不可辨、状态不可感 | ch06 §6.4 |

> **★★ 第 2 条是总纲**：它有 Web 原型 —— 浏览器工具栏的「去掉样式 + 关闭图片 + 纯文本 + 线性顺序」。

### 6. 三种策略的优劣序（ch03 §3.2.5 —— 全书的决策规则）

| 序 | 策略 | 验收标准 |
|---|---|---|
| **1（最优）** | **普适性（包容性）设计** | 同一设计对所有人生效（一致的设计和内容） |
| **2（次优）** | **等价使用** | **信息必须等价，体验允许有差** |
| **3（最不推荐）** | **适应**（做单独版本） | 「**彼此分离而号称平等的事物之间从来就没有真正的平等**」（ch08 p172） |

> **★★★ 第 3 种的正解（ch10 p213）：空手道界面** —— **同一产品分"可达层级"，不做两个版本；
> 功能一个都不少，只是浅层/深层。** 这是本书对"老人不会用复杂面板"这个现实问题的最优答案。

| **13** | **内置才普及**（ch05 p103 VoiceOver / ch09 p194 字幕 / ch12 p237「前置条件计数法」） | 可访问性功能进**标配**，不做"外接模块/另购配件"；数每个能力的**前置条件数**（默认开 = 0） | 出厂状态下，最弱用户能否直接用；前置条件是几个 |
| **14** | **结构可被改造**（ch04 p79 架构灵活性 / ch05 p113「没有一蹴而就」/ ch07 §7.6.1「有控制的灵活性」） | 预留**可换按键帽 / 可加标识位 / 可外接接口 / 可调角度高度**；不做一体封闭 | 问"用户想改它/适配它，能改哪儿"；答不出即不合格 |
| **15** | **⚠ 逆向边界：Web 能"让用户改"，实体产品不能**（ch07 p134：作者自述「**不同于纸质出版物和其他的有形产品，网页可以有非常灵活的变化**」） | **Web 上"用户可覆盖"（样式表/缩放/高对比）承担的职责，实体产品必须由"出厂可调 + 默认够用"全额承担** | 恢复出厂设置后，主任务能否完成；有哪些"用户在 Web 上能自己调、在产品上只能认命"的地方 |

> **★★★★ 第 15 行是本技能最重要的立论**：
> **它是作者自己划出的形态边界，也是本技能区别于所有 Web 无障碍教材的地方。**
> 实体产品拿不到"用户可改样式表"这张牌，**所以"默认够用 + 出厂可调"必须承担双倍责任。**

## 与 `inclusive-accessibility-design` 的分工（**理论 ↔ 实践**）

| 维度 | `inclusive-accessibility-design` | **`web-accessibility-cn`（本技能）** |
|---|---|---|
| **源书年代** | 2003 / 2007（英文） | **2014（中译 2015）** |
| **书的性质** | 理论专著（Springer / Gower） | **实践手册（12 章 Web 实操）** |
| **怎么表征用户** | **能力分数**（七轴 0–13 分量表）+ 人口百分比 | **名字 + 故事 + 四层人物快照**（8 个角色） |
| **怎么算** | **排除率量化**（四步评估法、WINIT 五层、P5–P95=10%=460 万、worst+0.4+0.3 算式） | **几乎不给人数的量化**（只有引用统计） |
| **怎么落地** | **7-Level 设计法 + Knowledge Loop** | **12 章判据 + 17 问组织诊断 + WCAG 条目与级别** |
| **用户从哪来** | **极端用户 / boundary users / 关键用户**（按能力分数与分布两端选） | **8 个具名角色 + 真实用户**（按"经验程度"选人） |
| **标准语境** | **不含 WCAG**（成书太早） | **含 WCAG 2.0 的 61 条 + A/AA/AAA 级别** |
| **核心资产** | 能力谱、排除率、7-Level、模拟器标定 | **WCAG 条目表、"造型+位置+文本"、ColorADD、空手道界面、"分离即不平等"** |

### 一句话分工

> **那本回答"为什么能算、排除多少人、流程怎么建"（理论）；**
> **本技能回答"照着做什么、这一条是 A 还是 AA、中文语境怎么讲"（实践）。**
>
> **凡遇到"要把人的能力量化 / 要估排除人数 / 要建流程表征 / 要选极端用户 / 要用模拟器"
> → 去 `inclusive-accessibility-design`（本技能不重述，只指路）。**
> **凡遇到"这一处的具体做法 / WCAG 条目的级别 / 中文文案怎么写 / 组织怎么诊断"
> → 留在本技能。**
