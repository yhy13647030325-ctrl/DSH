## 6.1 ★★★★★ 烘焙法线贴图（Baking a normal map）

> **原文**：
> 「**本节我们学习如何从高模物体创建法线贴图纹理。
> 这让我们能通过在其上放置一张贴图来模拟凹凸表面。**
> **以下步骤中，我们会创建碳纤维表面并烘焙成法线贴图，
> 这样就能轻松地把它作为贴图放到任何物体上。**」

### 6.1.1 ★★★★★ 八步全流程（本节的核心）

| 步 | 原文操作 | 关键参数 |
|---|---|---|
| **1** | **建两个平面 → 各加中间环切 → 把环切抬起** | **★ 做出"棱"** |
| **2** | **`Ctrl+B` 倒角 + 开平滑着色** | — |
| **3** | **顶视图加 Array → ★ 勾 Constant Offset（不是 Relative）** | **★ 关键切换** |
| **4** | **调 X/Y 距离让形状完美平铺 → 增大 Count** | — |
| **5** | **再加一个 Array → 同样调偏移完美平铺** | **★ 两个 Array 叠加** |
| **6** | **中间加平面 → ★ 按 2 的倍数缩放 → ★ 按住 Ctrl 吸附网格** | **★ 必须 2 的倍数** |
| **7** | **Image Editor 建图 `Carbon_Fiber` → 512 × 512** | **★ 512 是 2 的幂** |
| **8** | **平面建材质 → 加 Image Texture → 加载该图** | — |

**★★★★★ 三个"必须"（本节的硬要求）**：

**① Array 必须勾 Constant Offset（不是 Relative）**
> **原文**：「**加一个 Array 修改器并勾选 Constant Offset 而不是 Relative Offset。**」
> **★★ 因为"完美平铺（tiled perfectly）"需要绝对距离，不是相对倍数。**

**② 承载平面必须按 2 的倍数缩放**
> **原文**：
> 「**这个平面不能超出图案之外。
> 它必须按 2 的倍数缩放，以确保法线贴图是无缝的（seamless）。**」
> 「**移动平面时记得按住 `Ctrl`，这样它会吸附到网格。**」

| 要求 | 原因 |
|---|---|
| **★ 2 的倍数** | **★ 保证可无缝平铺** |
| **★ 不超出图案** | **★ 否则边缘采样出错** |
| **★ 略高于图案表面** | **★ 烘焙时需要"包裹"关系** |
| **★ Ctrl 吸附网格** | **★ 保证精确对齐** |

**③ 分辨率 512 × 512**
> **★★ 512 是 2 的幂**（纹理的标准尺寸）—— **★ 2 的幂在各种硬件/算法上最稳。**

### 6.1.2 ★★★★★ 烘焙设置（三个必设）

> **原文**：
> 「**在 Render Properties 标签打开 Bake 菜单。
> ★ 这个菜单只在 Cycles 渲染模式下出现。**
> **把 Bake Type 设为 Normal，并勾选 Selected to Active 复选框。**」

**★★★★★ Bake 的三个必设**：

| 设置 | 值 | 为什么 |
|---|---|---|
| **★ Render Engine** | **★ Cycles** | **★ Bake 菜单只在 Cycles 出现** |
| **★ Bake Type** | **★ Normal** | **★ 要的是法线不是颜色** |
| **★ Selected to Active** | **★ 勾选** | **★ 高模→低模的传送** |

**★★★★★ 选择顺序（最容易错的一步）**：
> **原文**：
> 「**先选图案，再选平面。
> 这让我们能把图案的表面以法线贴图的形式烘焙到平面上。**」

```
★ 先选"源"（高模图案）
   ↓ 再选"目标"（承载平面）
   ↓ ★ 顺序反了，烘焙方向就反了
```

> **★★★ 判据：`Selected to Active` 的含义是"从选中物体烘焙到激活物体"。**
> **★ 所以"最后选的那个"必须是"接收方（平面）"。**

### 6.1.3 ★★★★★ 用法线贴图（Normal Map 节点）

> **原文**：
> 「**把一个加载了法线贴图的 Image Texture 节点插进 Normal Map 节点。
> 再把 Normal Map 节点插进 Principled BSDF 节点的 Normal 插口。
> 在渲染视图里，你会注意到平面上有凹凸图案。
> 为突出法线贴图效果，降低 Principled BSDF 上的 Roughness 值。**」

**★★★★★ 三段式节点链（本章所有法线贴图的通用结构）**：

```
Image Texture（法线图）
   ↓
★ Normal Map 节点（必须有！不能直连）
   ↓
Principled BSDF 的 Normal 插口
```

> **★★★ 判据：法线贴图必须经过 `Normal Map` 节点转换** ——
> **★ 因为它要把"RGB 颜色"解释成"法线向量"，直连会被当颜色用。**

**★★★★ 一条"让效果明显"的技巧**：
> **原文**：「**为突出法线贴图效果，降低 Roughness 值。**」
> **★★ 因为粗糙度高时表面漫反射强，凹凸看不出来。**

## 6.2 ★★★★★ UV 展开（UV unwrapping）

> **原文**：
> 「**本节学习如何为贴图 UV 展开物体。
> 这个技术可以用于无缝地给任何物体贴图。**」
> **原文（概念）**：
> 「**我们必须先理解 UV 展开是什么、如何工作。
> 当我们 UV 展开一个物体时，我们把它变成一个 2D 表面。
> 你可以把它想成"反向纸模型（reverse papercraft）"。
> 然后我们把物体的 2D 版本放到一张图像贴图上，
> 告诉 Blender 我们希望贴图如何出现在物体表面。**」

### 6.2.1 ★★★★★ 一个精准的类比（原文）

> **★★★ 「UV 展开 = 反向纸模型（reverse papercraft）」**

| 纸模型 | **UV 展开** |
|---|---|
| **2D 纸 → 折成 3D** | **★ 3D → 展开成 2D** |
| **折痕 = 剪口** | **★ 剪口 = 缝合线（Seam）** |

> **★★ 这个类比说明了"Seam（缝合线）"的本质**：
> **★ 它就是"剪纸时该在哪里剪开"。**

### 6.2.2 ★★★★★ UV 展开只有两步（原文）

> **原文**：
> 「**一个物体可以用两个简单步骤 UV 展开：**
> **1. 选中展开时需要剪开的边。
> 在 Edit Mode 按 `U` 打开 UV Mapping 菜单，选 Mark Seam。
> 标记缝合线后，在同一个菜单里选 Unwrap。**
> **2. 在 Shading Editor 里把 Image Editor 切成 UV Editor。
> 选中立方体时，它现在会以展开版本出现在 UV Editor 里。**」

**★★★★★ 两步（第一步含三个动作）**：

```
① 选边 → U → Mark Seam → U → Unwrap
   ↓
② Shading Editor 里切换成 UV Editor → 看展开结果
```

| 键 | 功能 |
|---|---|
| **★ `U`** | **★ UV Mapping 菜单（含 Mark Seam / Unwrap）** |

> **★★★ 判据：`U` 菜单里有两个动作要依次做 —— 先 Mark Seam 再 Unwrap。**
> **★ 只 Unwrap 不 Mark Seam，展开结果会很碎。**

### 6.2.3 ★★★★★ 把 UV 用于扩散器（五步）

| 步 | 原文操作 | 关键 |
|---|---|---|
| **1** | **在扩散器上标缝合线 → Unwrap** | **★ 缝合线标在"看不见的边"** |
| **2** | **新建材质 → Image Texture 加载碳纤维图** | — |
| **3** | **★ Color Space 设为 Non-Color → 过 Normal Map 节点** | **★ 关键设置** |
| **4** | **加 Texture Coordinate + Mapping 节点** | **★ 控制贴图** |
| **5** | **调 Mapping 里的 Scale 来缩放纹理** | — |

**★★★★★ 一条必设：`Color Space = Non-Color`**

> **原文**：「**把 Color Space 设为 Non-Color，然后让图像通过一个 Normal Map 节点。**」

| Color Space | 用于 |
|---|---|
| **sRGB** | **★ 颜色贴图（Base Color）** |
| **★ Non-Color** | **★ 数据贴图（法线/粗糙度/遮罩）** |

> **★★★ 判据：法线贴图必须设 `Non-Color`** ——
> **★ 否则 Blender 会给它做 sRGB → 线性转换，法线方向就错了。**
> **★ 这是"法线贴图看起来不对"的最常见原因。**

**★★★★ Mapping 节点的作用**：
> **原文**：「**加 Texture Coordinate 和 Mapping 节点，以便更好地控制贴图。
> 例如，我们可以通过改 Mapping 节点里的 Scale 数值来放大纹理。**」

| 节点 | 作用 |
|---|---|
| **Texture Coordinate** | **★ 提供坐标源（UV/Generated/Object）** |
| **★ Mapping** | **★ 平移/旋转/缩放贴图** |

## 6.3 ★★★★★ 烘焙倒角贴图（Baking a bevel map）

> **原文**：
> 「**现在学习如何用法线贴图模拟平滑的倒角（bevels）。**」
> 「**此时物体有凹凸表面，但它的边缘看起来太锐利、不真实。
> 我们可以通过加倒角让边看起来更好，但那会让多边形数量增加太多。
> 我们可以用已学过的同一套法线贴图技术模拟平滑的倒角边。**」

### 6.3.1 ★★★★★ 这是 ch01"倒角矛盾"的正式解法（全书暗线的收束）

**回顾 ch01 提出的矛盾**：
> **★★ 「倒角加真实感，但增加大量多边形 → 渲染吃力。**
> **★ 所以倒角常被烘焙成法线贴图。」**

**★★★★★ 本章给出了完整实现**：

| 阶段 | 章 | 内容 |
|---|---|---|
| **提出矛盾** | **ch01** | 倒角 vs 多边形 |
| **提到方向** | **ch01** | "烘焙成法线贴图" |
| **★ 完整实现** | **★ ch06 §6.3** | **★ 本节** |

> **★★★ 判据：几何上不加倒角，用"法线贴图"伪造倒角的视觉效果。**
> **★ 结果：多边形数量不变，但渲染时边看起来是圆的。**

### 6.3.2 ★★★★★ 六步做法（本节核心）

| 步 | 原文操作 | 关键 |
|---|---|---|
| **1** | **复制物体 → 在副本上用 `Ctrl+B` 给锐边加倒角** | **★ 副本 = "高模源"** |
| **2** | **把两个物体移到完全相同的位置** | **★ 必须重合** |
| **3** | **选原物体 → Edit Mode → `Alt+S` 稍微外扩** | **★ 让副本被原物体完全包住** |
| **4** | **新建图用于烘焙倒角法线** | — |
| **5** | **材质里把新图加载进 Image Texture（替换碳纤维）→ 重复烘焙步骤** | — |
| **6** | **把倒角法线贴到"未加倒角"的物体上** | **★ 得到平滑边** |

**★★★★★ 步骤 3 的原理（本节最难理解的一步）**：
> **原文**：
> 「**选原物体，在 Edit Mode 里用 `Alt + S` 把所有东西稍微外扩。
> 这会确保复制的物体被原物体完全包含。
> 就像我们烘焙上一个法线贴图时把平面移到碳纤维网格上方一样，
> 我们需要让"表面"稍微高于"高模网格"。**」

```
低模（要贴图的物体）        ← ★ 用 Alt+S 外扩一点
   ↓ 把它"包住"
高模（带倒角的副本）
   ↓ 烘焙时：Selected to Active
★ 高模的细节 → 低模的 UV
```

| 要求 | 原因 |
|---|---|
| **★ 低模必须"包住"高模** | **★ 这样高模所有法线细节都能被"投射"到低模** |

> **★★★ 判据：烘焙倒角时，"要接收贴图的物体"必须比"来源物体"稍微大一圈。**
> **★ 否则高模的凸起部分会"穿到外面"，烘焙不到。**

### 6.3.3 ★★★★★ 混合两张法线贴图（本节的进阶技巧）

> **原文**：
> 「**我们可以很容易地把碳纤维法线贴图和倒角法线贴图合并。
> 做法：为每张法线贴图创建独立的 Image Texture 节点
> （各配 Mapping 和 Geometry 节点），
> 在送进 Normal Map 节点之前，用一个 MixRGB 节点把它们连接起来。**」

**★★★★★ 多法线混合的标准接法**：

```
法线图1 → Normal Map 1 ─┐
                        ├─→ ★ MixRGB ─→ Normal Map ─→ Principled BSDF
法线图2 → Normal Map 2 ─┘
```

> **★★ 判据：多张法线贴图，先各自过 Normal Map 节点，再用 MixRGB 混合** ——
> **★ 不能"先混 RGB 再转法线"（那样法线数据会被破坏）。**

**★★★★ 原文的总结**：
> **「我们现在可以为一个物体烘焙多种不同的法线贴图，并用节点把它们一起渲染在一个表面上。」**

> **★★★ 这是本章的"能力边界扩展"**：
> **★ 一个表面可以叠加：凹凸 + 倒角 + 贴花 + ……（无限层）**

### 6.4.2 ★★★★★ Box Mapping（本节最实用的效率技巧）

> **原文**：
> 「**你可以轻松地把碳纤维贴图应用到任何物体上，而不需要 UV 展开。**
> **在 Carbon Fiber 材质里，把 Texture Coordinate 节点的 Object 输出（而不是 UV）
> 插进 Mapping 节点。
> 在 Image Texture 节点里，把 Mapping 设为 Box。
> 这会根据物体的形状把贴图投射上去。
> ★ 虽然这让贴图容易得多，但它并不总是像手动 UV 展开那样完美。**」

**★★★★★ Box Mapping 的完整设置**：

| 项 | 设成 |
|---|---|
| **Texture Coordinate 输出** | **★ `Object`（不是 `UV`）** |
| **Image Texture 的 Mapping** | **★ `Box`** |

**★★★★★ 两条判据（原文明确给了权衡）**：

| 优点 | 缺点 |
|---|---|
| **★ 不需要 UV 展开** | **★ 不如手动 UV 完美** |

> **★★★ 判据：Box Mapping 是"快速贴图"的省事办法，不是"最佳质量"。**
> **★ 用于"看不出展开差异"的材质（如碳纤维这种细密重复纹理）。**

### 6.4.5 ★★★★★ 画线（Stroke Method）

> **原文（步骤 1–3）**：
> 「**1. 用大号黑笔刷涂一遍，确保图像全黑。**
> **2. 在窗口顶部工具栏找到 Stroke Method 菜单，把它从 Space 改成 Line。
> 这会让我们画直线。**
> **3. 用白笔刷点击并拖动左键，在装甲板边缘画直线。**」

**★★★★★ Stroke Method 的两种模式（本节的量化知识）**：

| 模式 | 效果 | 用途 |
|---|---|---|
| **Space** | **★ 按间距连续落笔** | **★ 自由绘制** |
| **★ Line** | **★ 画直线** | **★ 画边缘线/描边** |

> **★★ 判据：画"硬边描线"必须用 Line 模式** ——
> **★ Space 模式画出来是抖的。**

**★★★★ 一条视角技巧（原文 TIP）**：
> **「用 `Shift + 7` 把视图对齐到选中的面，按 `Num 5` 进入正交视图。
> 这会在纹理绘制时给你更好的角度。**」

| 键 | 功能 |
|---|---|
| **`Shift + 7`** | **★ 视角对齐到选中面** |
| **`Num 5`** | **★ 切换正交/透视** |

> **★★ 判据：在平面上画线时，必须"正视 + 正交"** ——
> **★ 否则笔迹会因透视变形。**

### 6.4.6 ★★★★★ 用 MixRGB 给黑白贴图上色

> **原文**：
> 「**在 Image Texture 节点和 Principled BSDF 节点之间加一个 MixRGB 节点。
> 把贴图颜色输出插进 MixRGB 的 Fac 输入，
> 这让我们能用任何其他颜色替换所画的黑色和白色。
> 我们也可以把颜色替换成贴图。
> 例如生成一个 Checker Texture 节点，把它插进 MixRGB 的某个输入。**」

**★★★★★ "黑白遮罩 + MixRGB = 任意配色"（本章的核心技巧）**：

```
黑白遮罩图 → ★ MixRGB 的 Fac
                    ↓
              Color1（黑处显示）+ Color2（白处显示）
                    ↓
              ★ 任意配色方案
```

> **★★★ 判据：用"黑白图当遮罩"比"直接画彩色"更灵活** ——
> **★ 因为改配色只需改 Color1/Color2，不用重画。**

**★★★★ 一条"高级用法"**：
> **原文**：「**我们也可以把颜色替换成贴图。
> 例如生成一个 Checker Texture 节点，插进 MixRGB 的某个输入。**」

> **★★ 判据：MixRGB 的两个输入可以接"任意节点"** ——
> **★ 所以"遮罩 + 程序化纹理"能生成无限组合。**
> **★ 这与 ch04 "Principled BSDF 任何插口都能接任何节点"同理。**

### 6.4.7 ★★★★★ 烘焙材质为贴图（关键的一步）

> **原文**：
> 「**在材质里再加一个 Image Texture 节点，让它保持不连接。
> 新建一张图，并按图 6.43 改烘焙设置。
> 这让我们把材质保存成图像，然后在其上自由绘制。**
> **烘焙后，把所有其他节点替换为只加载烘焙贴图的 Image Texture 节点。**」

**★★★★★ 为什么要"再烘一次"（本节的逻辑）**：

```
材质里有大量节点（MixRGB + Checker + ...）
   ↓ ★ 这些节点"不能画"
   ↓ 用 Bake 把它们"压平成一张图"
   ↓
★ 变成一张可以"往上画"的底图
```

| 步 | 操作 | 目的 |
|---|---|---|
| **1** | **加 Image Texture 节点，★ 不连接** | **★ 告诉 Blender"烘到这张"** |
| **2** | **Bake** | **★ 节点效果 → 图像** |
| **3** | **★ 用单张 Image Texture 替换所有节点** | **★ 变成"可画"的底图** |

> **★★★ 判据：要"在程序化材质上画东西"→ 先 Bake 成图，再画。**
> **★ 因为笔刷只能作用于图像，不能作用于节点。**

**★★★★★ 法线错误的表现与修复（本节最有价值的排错知识）**：

> **原文**：
> 「**烘焙法线贴图有时会产生奇怪的结果。
> 这意味着网格的法线方向不正确。**
> **做法：在 Edit Mode 打开 Viewport Overlays 菜单，启用 Face Orientation。
> 启用后，方向正确的法线显示为蓝色，不正确的显示为红色。**」

**★★★★★ 法线问题三步排查（本章总结出的方法）**：

| 步 | 操作 | 结果 |
|---|---|---|
| **1** | **Viewport Overlays → 开 Face Orientation** | **★ 蓝=对、红=错** |
| **2** | **`Shift + N` 自动重算** | **★ 多数情况解决** |
| **3** | **★ 仍红的：选中按 `Ctrl + W` 手动翻转** | **★ 兜底手段** |

> **★★★ 判据：`Shift+N` 修不好时，用 `Ctrl+W` 手动翻** ——
> **★ 因为 `Shift+N` 是"按几何推断朝向"，遇到"内外不分"的复杂形状会失败。**

> **★ 判据：Face Orientation 是全书通用的"法线体检"工具。**

### 6.6.2 ★★★★★ 画法线贴花（第二段：画法，含一个必记的颜色值）

**★★★★★ `8080FF` 是什么（本节最重要的知识点）**：

> **原文**：
> 「**这次我们不用黑图，而是把它的 Hex 代码设为 `8080FF`。
> 这给我们一个"可以在其上画法线凹凸"的基底。**」

**★★★★★ 法线贴图的"中性值"**：

| 颜色 | RGB | 含义 |
|---|---|---|
| **★ `8080FF`** | **(128, 128, 255)** | **★ 法线"无偏移"的中性色** |

> **★★★ 为什么是 `8080FF`**：
> **法线贴图把"方向向量"编码成 RGB。**
> **★ R=X、G=Y 的中性值是 0.5（即 128 = `80`）**；
> **★ B=Z 的中性值是 1.0（即 255 = `FF`）。**
> **★ 所以 `8080FF` = "法线朝正上方、无任何偏转" = 平面。**
>
> **★★ 判据：画法线细节的"画布底色"必须是 `8080FF`** ——
> **★ 用纯黑或纯白都会让法线指向莫名其妙的方向。**

**★★★★★ 一个"翻转模板"的技巧（原文）**：
> **原文**：
> 「**在 Y 轴上把图像缩放到 -1.00，来把它画到飞船的另一侧，
> 就像我们建模时翻转物体的方式一样。**」

> **★★ 判据：贴花要"镜像到另一侧"→ 模板 Y 轴缩放 -1** （不是重新下载素材）。

**★★★★ 原文的结论（本章的价值主张）**：
> **「画完法线贴花后，看起来就像我们把舱盖建模进了装甲里。
> 这是一个在**不添加任何新物体、不增加模型多边形数量**的前提下创建大量细节的好方法。」**

> **★★★ 这是本章的一句话精华**：
> **★ 细节可以"看起来有"而不"实际有"。**
