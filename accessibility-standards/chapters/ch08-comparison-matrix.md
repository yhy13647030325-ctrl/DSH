## 8.1 总纲：三个数字与三类差异

### 8.1.1 三个数字

| 版本 | 条目数 | A | AA | AAA | 无级别（已废止） |
|---|---|---|---|---|---|
| WCAG 2.0（2008） | **61** | 25 | 13 | 23 | 0 |
| WCAG 2.1（2018） | **78** | 30 | 20 | 28 | 0 |
| WCAG 2.2（2023） | **87** | 31 | 24 | 31 | **1** |

### 8.1.2 三类差异（不是只有『新增』）

| 差异类型 | 2.0 → 2.1 | 2.1 → 2.2 |
|---|---|---|
| **新增条目** | **17** | **9** |
| **废除条目** | 0 | **1**（4.1.1 Parsing） |
| **改名** | 2 处（仅大小写/空格规范：1.2.7、1.4.4） | 2 处（**2.5.5 → Target Size (Enhanced)**、4.1.1 → Parsing (Obsolete and removed)） |
| **级别变化** | 0 | **1**（4.1.1：A → 无级别） |

> **★★★ 判据：看版本升级，必须同时看『加了几条』『废了几条』『改了几条』。**
> 只说『2.2 新增 9 条』会漏掉『同时废止了 1 条、并给 2.5.5 改了名』——
> 而改名直接导致『几乘几』的规格对不上（见 ch01 §1.2.15）。

### 8.1.3 一条容易被忽略的规模事实

**2.0 的 61 条中有 23 条是 AAA**（占 38%）。
这意味着『符合 WCAG 2.0 AA』实际只需过 **25 + 13 = 38 条**；
而『符合 2.2 AA』要过 **31 + 24 = 55 条**（不含已废止的 4.1.1）。

> **★ 判据：从『2.0 AA』升到『2.2 AA』，需要新增满足的条目，可直接从下表逐条筛。**
> 口径：2.1 新增的 A/AA 条目 **12 条**（A=5：2.1.4/2.5.1/2.5.2/2.5.3/2.5.4；AA=7：1.3.4/1.3.5/1.4.10/1.4.11/1.4.12/1.4.13/4.1.3）；
> 2.2 新增的 A/AA 条目 **6 条**（A=2：3.2.6/3.3.7；AA=4：2.4.11/2.5.7/2.5.8/3.3.8）。
> 合计 **18 条**需要新增满足。
> **本技能仍建议用下表逐条筛** —— 因为如果你的基线不是『全 2.0 AA 已达标』，实际缺口会不同。

## 8.3 与 `web-accessibility-cn` 的分工（谁讲哪条）

`web-accessibility-cn` 蒸馏自《兼济天下·用户无障碍体验的可访问性设计》（成书 2014，基于 **WCAG 2.0**）。

| 内容 | 该查谁 | 理由 |
|---|---|---|
| **WCAG 2.0 的 61 条**在中文语境下的落地 | **`web-accessibility-cn`** | 那本的条目与案例全部基于 2.0，且给了中文场景的角色与方法 |
| **对比度 4.5:1 / 7:1 / 3:1 的**设计用法 | **`web-accessibility-cn`** ch07 的数值表 | 那本按设计场景组织，比条文更好用 |
| **2.1 新增 17 条 / 2.2 新增 9 条** | **本书 ch01 / ch02** | 那本成书时还不存在这些条目 |
| **4.1.1 废止** | **本书 ch02 §2.3** | 废止发生在 2023 |
| **EN 301 549 / 一致性模型 / 采购** | **本书 ch03 / ch04** | 那本不含 |
| **向实体产品迁移的条文依据** | **本书 ch04 §4.2.2–4.2.3 + ch08 §8.4** | 那本的迁移是**从 Web 原理推演**；本书给**标准原文的硬件条款** |
| 三个可访问性方程、8 个中文用户角色、简洁四策略 | **`web-accessibility-cn`** | 那是该书独有内容，本书不重复 |
| 『竣工后加木梯』判据、三途径、双绑定 | **`web-accessibility-cn`** | 同上 |

> **★★ 判据：两本不是替代关系，是『设计原理（旧）』+『标准条文（新）』的两层结构。**
> 引用时的正确姿势：**原理与中文语境查旧技能，条目号/级别/阈值/版本查本技能。**

## 8.4 与 `inclusive-accessibility-design` 的分工

`inclusive-accessibility-design` 蒸馏自 *Inclusive Design: Design for the Whole Population* 与 *Design for Inclusivity*（2003 / 2007）。

| 内容 | 该查谁 | 理由 |
|---|---|---|
| **能力谱系、七条能力轴、排除率估算** | **`inclusive-accessibility-design`** | 方法论源头，本书不替代 |
| **用户金字塔、十级严重度、加权公式** | 同上 | 同上 |
| **能力损失模拟器、四步排除评估法** | 同上 | 那本的实操核心 |
| **『哪条标准对应哪种能力损失』** | **本书 ch04 §4.2.1** | EN 301 549 第 4 章的 11 条功能性能陈述是**标准条文版的能力轴** |
| **具体的尺寸/对比度/时间数值** | **本书** | 那本成书时无这些标准 |
| **为何 AAA 不能当门槛** | **本书 ch03 §3.3** | 那本讲『包容度比值趋近 1』，本书讲标准为何不设顶格要求 |

> **★★★★ 全书级判据：EN 301 549 第 4 章的 11 条功能性能陈述，与包容性设计的能力轴是同构的 ——
> 但前者是可以写进采购合同的条文，后者是设计前期的建模工具。**
> 这是本书与那本旧技能之间最有价值的一条桥：**用旧技能找问题，用本书定指标。**

两者的对应关系（本技能的对照，非任何原文所述）：

| EN 301 549 §4.2 | 对应的能力轴（`inclusive-accessibility-design`） |
|---|---|
| 4.2.1 无视觉 / 4.2.2 有限视觉 | **vision** |
| 4.2.3 无色彩感知 | **vision**（色觉子项） |
| 4.2.4 无听觉 / 4.2.5 有限听觉 | **hearing** |
| 4.2.6 无/有限发声 | **communication** |
| 4.2.7 有限操作力 / 4.2.8 有限触及 | **dexterity** + **reach** |
| 4.2.9 光敏癫痫 | **vision**（光敏子项） |
| 4.2.10 有限认知/语言/学习 | **intellectual** |
| 4.2.11 隐私 | （能力轴之外的横切要求） |

> **★ 注意：上表是**本技能的对照**，EN 301 549 原文并未使用『能力轴』这一术语；
> 它用的是 permanent, temporary or situational 三态（见 ch04 §4.2.1）。**
