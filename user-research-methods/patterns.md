# 可复用模式 / 配方

> 源 A = UMoD（页码 PDF 索引，书内页 = PDF − 1）｜源 B = Goodman 2nd ed（EPUB，`DOC N §M`）
> 每个模式含：**适用场景 / 步骤 / 判据 / 出处**

---

## P1 · 研究设计七步链路（总配方）

**适用**：任何一次从零开始的研究项目。

```
① 定问题   → 写成"可被哪类数据回答"的句子（ch01 §1.2 五维定位）
② 选方法   → ch01 五阶段 + 五类角色；查 cheatsheet §3 四问表
③ 定样本   → ch06 查表；查不到就用"停止条件"（§6.5）
④ 写脚本   → 访谈：ch02 §2.2.2；日记：ch04 §4.2.2；问卷：ch05 §5.2–§5.4
⑤ 执行     → ch10 §10.3 约人 → §10.4 准备 → §10.5 六禁
⑥ 分析     → ch07 §7.2 外化 → 聚类 → §7.5 主题 → §7.6 三角
⑦ 交付     → ch08 选画像/旅程/任务图；ch09 若需验证
```

**判据**：每一步的产出物类型必须与下一步匹配。**卡点最常见于 ②→③**：想清楚了方法，却找不到样本量依据 → 说明选的方法本身没有公认样本量，此时**改方法是正解，不是硬凑数字**。

## P2 · 样本量决策树（当原书没给数字时）

**适用**：要为一个"两书都没给人数"的方法定样本量。

```
Q1 能否找到同类研究的公认数字？
   ├─ 能 → 直接用，并注来源（不用本书背书）
   └─ 不能 → 进 Q2

Q2 目的是"覆盖"还是"饱和"？
   ├─ 覆盖 → 每细分/每因素 ≥4 人（双源印证：A p117 / B DOC 16 §61）
   │         细分 × 4 = 总量
   └─ 饱和 → 进 Q3

Q3 有"产出量门槛"吗？
   ├─ 有 → 用它（每人 60~120 行为 / 50~100 观察 / ≥6 条日记）
   └─ 无 → 进 Q4

Q4 有"停止规则"吗？
   ├─ 有 → 用它（RITE：连续 5 次成功）
   └─ 无 → 先做一轮小样本（4~6），
           看"是否还出现新主题"
           ├─ 是 → 加一轮（B DOC 16 §62：schedule a second round）
           └─ 否 → 停，并在报告里注明"依据饱和度判断，非查表"
```

**判据（红线）**：Q4 走到"无"时，**报告必须写明"本项无权威样本量依据，按饱和判断"**。
不许把 4~6 写成"原书建议"。

## P3 · 访谈脚本配方（三段式）

**适用**：深度访谈、情境访谈的起始访谈、可用性测试的访谈部分。

| 段 | 时长占比 | 内容 | 关键动作 |
|---|---|---|---|
| **开场** | 10% | 说明目的、时长、设备、同意书；**请他"不要做准备"** | B `DOC 16 §67` |
| **主段** | 75% | 由具体事件驱动：**"上一次……是什么时候？"** | A `p69` |
| **追问** | 穿插 | 三个扳机词：**惊讶 / 古怪 / 矛盾** → 追问 | A `p47` Focus 原则 |
| **收尾** | 15% | **"我漏问了什么？"** | A `p173` Request for questions |

**三条硬规则**：

1. **跨被试可比 → 逐字念稿**（A `p103`）
2. **不说"一般你会怎么做"，只说"那一次"**（A `p69`；否则拿到概括版）
3. **他问你怎么解决 → 反回去**：「你希望它怎么表现？」（B `DOC 16 §105`）

## P4 · 日记本设计配方（六件套）

**适用**：任何跨时间（1 天 ~ 1 月）的自报研究。

| # | 组件 | 要求 | 出处 |
|---|---|---|---|
| 1 | **主题说明** | 开篇一页，讲清研究关心什么 | A `p67` |
| 2 | **写作指令** | 何时写、怎么写 | A `p67` |
| 3 | **示范条目** | **一条完整样例**（最易省、最不该省） | A `p67` |
| 4 | **页面引导** | 每页一个简短提示词 + **按需留白** | A `p67` |
| 5 | **记录节律** | 事件触发 / 时间触发 / 日终汇总 / 随机信号（**证据强度依次递减**） | A `p67` |
| 6 | **末端信息** | 少量反思问题 + 人口统计 | A `p67` |

**工作量预算（必算）**：
`人数 × 天数 × 每日次数 = 条目总量`；典型 **10 × 7 × 3 = 210 条**（B `DOC 17 §27`）。
**并预留"监控 + 追问"的人力**——原文警告不要低估在线日记的监控成本。

**判据**：条目小于 **6 条/人**，趋势看不出来（B `DOC 17 §36`）。

## P5 · 问卷配方（五步 + 七检查）

**五步**：

```
① 定题型 → 比较偏好？用排序或定额分配（A p141）
② 写措辞 → 对照 13 类；删掉 leading / blaming（A p173）
③ 排题序 → 从广到窄；最后一题问"我漏了什么"
④ 定版式 → 六个维度逐项过（措辞/选项/题序/长度/版式/设计）
⑤ 预调查 → 流程与正式完全相同，5~10 份，连报告模板都跑一遍（B DOC 19 §219）
```

**七项交付前检查**：

- [ ] 有没有 leading / blaming 题？（硬禁）
- [ ] 比较偏好的题是不是单选？（应改排序/定额）
- [ ] 李克特是不是五点、锚点是否为 strongly disagree ↔ strongly agree？
- [ ] Neutral 是否逐题检查过（去掉价值词）？
- [ ] Factual 与 Hypothetical 是否分清（能验证 vs 只是意愿）？
- [ ] 有无"请求提问"的收尾题？
- [ ] 外观/清晰度/说明/编排/设计/版式 六项是否都过了一遍？

## P6 · 亲和图配方（从便签到主题）

**适用**：访谈/观察/可用性观察室的数据聚类。

```
① 一签一事（"让每条的 design implication 被单独考虑"，A p13）
② 每条带编号：U{被试号} {记录序号}（如 U2 221；A p13 图内实例）
③ 贴在覆盖大幅纸的墙上（"可整张搬走"，A p13）
④ 自下而上聚类：先聚细节，后长主题（A p13）
⑤ 四层上色：黄(单条)→蓝(侧面)→粉(具体问题)→绿(总体关切)
⑥ 主题句用**第一人称**写（图内实例："organize my information" "don't interrupt me"）
⑦ 收手标准：「The diagram itself is not the point; insight is」（B DOC 22 §141）
```

**可用性测试变体**：**一被试一颜色** → 颜色多的类别 = 多人中招 = 优先修（A `p13`）。
**排期换算**：100 张便签 ≈ 1 人日（A `p13` 图注，InContext 实践）。

## P7 · 田野访问配方（选人 → 到场 → 复盘）

```
① 选策略 → 解决具体问题＝典型用户；找新机会＝极端/领先用户（B DOC 16 §53）
② 定人群 → 五问：人口构成 / 关键活动 / 常用工具 / 偶用工具 / 怎么用
          （四问是行为，人口统计只做定位，B DOC 16 §46–§52）
③ 定人数 → 快速 4 人/因素；充裕 5~8 人/因素（B DOC 16 §61–§62）
④ 约时间 → 第一原则："他那时确实在做我要看的事"（B DOC 16 §64）
⑤ 提前告知 → 目标/时长/设备/想看什么；**明确请他不要准备**（§67）
⑥ 现场 → 建立师徒或伙伴关系；避开六种角色（§99–§108）
⑦ 出意外 → 偏了但可救＝追问"平时怎样"；偏太远＝改期（§80–§81）
⑧ 结束后 → 立即记笔记 + 与观察者讨论 10~20 分钟（B DOC 18 §304）
```

**准备清单**见 cheatsheet §6。

## P8 · 交付物选型配方

**先问：干系人最需要回答哪一类问题？**（B `DOC 25 §16` 表 17.1 的结构）

| 问题类型 | 选什么交付物 |
|---|---|
| **这些人是谁？不同群体怎么用？** | 人物画像 |
| **什么情况下用？最看重/最不看重什么？** | 画像 + 场景 |
| **哪些事做起来难/容易？新老用户有差别吗？** | 场景 + 任务分析图 + 可用性评估 |
| **除了我们的产品，他们还用什么来完成同一件事？** | 场景 + 流程图 + 体验模型 |

**画像四要素**：姓名 / **图库照片** / 叙事（处境+目标+行为）/ 补充图像；一页内（A `p133`）。

**旅程图五项检查**：范围界定（全周期 or 单场景）／标注画像／接触前中后／正负中三态／**含犹豫困惑挫败**（A `p197`）。

## P9 · 验证方法选型配方

```
Q1 有没有可测对象？
   ├─ 没有 → 回 P1（这是探索问题，不是验证问题）
   └─ 有 → Q2

Q2 要定位"哪里失败"，还是要"接不接受这个新方式"？
   ├─ 哪里失败 → Q3
   └─ 接不接受 → 木马（A p205），前提是"造真机太贵/还没实现"

Q3 用户约得到吗？团队能到场观察吗？
   ├─ 能 → 可用性测试（每轮≥5，招募 6~10）
   │        └─ 还能几小时内改原型？→ 改用 RITE（连续 5 次成功）
   └─ 不能 → Q4

Q4 有既定的可用性最佳实践吗？
   ├─ 有（且能按产品情境改写）→ 启发式评估（3~5 位评估者，不用用户）
   └─ 系统是 walk-up-and-use、首次使用无人指导？→ 认知走查（四问逐步）

★ 认知走查/启发式 与 可用性测试 "发现不同类别的问题"，
   原文："using them together—rather than in lieu of one another—is always recommended"（A p33）
```

**可用性测试的执行细节 → 详见 `usability-testing` 技能，本技能不重复。**

## P10 · 三角验证配方（防"自说自话"）

```
① 选配对 → 最常见：观察 + 自报（A p189）
② 定类型 → 数据 / 研究者 / 理论 / 方法（四选一或组合；方法三角最常用）
③ 找冲突 → 自陈说 A、行为做 B → **不要取平均，冲突本身是发现**（A p189）
④ 追来源 → 冲突常来自：政策 / 社会规范 / 研究期望（A p189 原文点名）
⑤ 报差异 → 报告里单列"自陈 vs 行为"差异表
```

**最便宜的一步**：**研究者三角**——同一批材料给第二个人编码，立刻暴露解释偏见。

## P11 · 认知走查配方（四问逐步）

```
① 选任务 → 从**用户视角**写（不是"点设置→选语言"，而是"我想换成中文"）
② 列步骤 → believable sequence（A p33）
③ 逐步问四问：
   1. 用户想不想要这个效果？（动机）
   2. 用户看不看得见这个控件？（感知/可视性）
   3. 知不知道该控件会产生他要的效果？（匹配/概念模型）
   4. 做完知不知道成功了？（反馈/评估鸿沟）
④ 记录 → 每一步 × 四问 = 一张表；标出失败步骤
```

**四问 ↔ 诺曼行动七阶段**：1=目标层；2,3=执行层；4=评估层（接 `design-psychology-norman`）。

## P12 · 交接交接配方（研究 → 设计）

**适用**：研究做完，怎么让设计真的用上。

```
① 外化 → 结论写成便签/图，不写成文字报告（A p13）
② 具象 → 画像给"人"，旅程图给"瞬间"，任务分析给"步骤"
③ 可涂写 → 早期版本打印大图钉上墙，让所有人上手标注（A p197）
④ 可引用 → 画像要有名字，团队日常能说"这个对 Leonard 不友好"（B DOC 25 §37）
⑤ 长期在场 → 「not as a prop, but as the voice of the customer」（A p13）
```

**判据（成功标志）**：
- 画像：「you will know that your personas are effective if you hear stakeholders **referring to them by name** in the course of productive design and strategy discussions」（B `DOC 25 §38`）
- 旅程图：团队能指出"**哪个瞬间最该修**"（A `p197`）

## P13 · 抽样口径对齐人机工程（跨技能配方）

**适用**：研究结果要用于**尺寸/尺度/可达性**设计时。

```
① 查产品类型 → Ⅰ型(双限值)/ⅡA型(定上限)/ⅡB型(定下限)/Ⅲ型(平均)
                （见 ergonomics-ding-yulan §2 百分位选择模型）
② 定百分位  → 上限用高百分位(P95/P99)，下限用低百分位(P1/P5)
③ 改抽样    → **停止条件从"主题饱和"改为"覆盖到百分位端点"**
               · 必须包含大身材端个体（防"挡不住"）
               · 必须包含小身材端个体（防"够不到"）
               · 男女通用产品：男 P99 定上限、女 P1 定下限，**两端都要有人**
④ 验样本    → 检查样本的尺寸分布是否真的跨到了端点，
               还是"招来的都是中等身材"
```

**判据（红线）**：**"主题饱和"不能替代"百分位覆盖"。**
只按"招募方便"取样，会系统性丢掉 P5 以下与 P95 以上的用户 —— 而他们正是尺寸设计的约束来源。

**为什么这是红线**：本技能 ch06 §6.5 的覆盖型停止条件此时必须**升级**——
覆盖的不是"细分"，是**人体尺寸分布的端点**。
